# 文献批判靶子：自动化偏差、搜索减少与信息校准

## 用途说明

这是一份第一篇相关的**工作备忘录**，用于后续写：

- literature review
- gap
- criticism / positioning
- PPT 中的 `existing work -> traditional view -> gap`

它**不是**正式文献库入库记录，也**不替代**共享文献库 agent 的 bib / PDF 维护流程。

如果后续需要把这些文献正式纳入共享文献库，应再单独向文献库 agent 提出入库任务。

## 核心总判断

这组文献共同构成一个很有用的批判对象：

> 许多 automation bias / decision aid / verifiability / technology dominance 文献，很容易滑向一种隐含叙事：
> `AI/decision aid -> less search / less independent checking -> worse decision`

而第一篇当前更强的批判切口是：

> 问题不只是“人有没有少搜索”，而是 AI 是否改写了用户所看到、所比较、所质疑的信息结构；尤其是，AI summary 是否遗漏了关键反例、冲突证据、少数派信息和高诊断性线索，从而改变了用户对 `evidentiary sufficiency` 的判断。

## 后续最适合怎么用

### 1. 用于第一篇 literature review 的反向定位

这几篇文献最适合被组织成这样一段逻辑：

1. 现有文献已经注意到 automation bias、structural restrictiveness、verification complexity 和 technology dominance。
2. 这些文献普遍意识到：AI / decision aid 可能削弱独立检查、降低信息搜索、改变 reliance。
3. 但它们很多仍把问题主要理解成：
   - 搜索强度下降
   - 核验强度不足
   - 用户 vigilance 不够
4. 第一篇要进一步推进的是：
   - 真正需要被识别的不是“搜索少不少”，而是 `AI summary 是否改变了用户对额外证据价值、信息充分性和隐藏信号结构的判断`
   - 也就是从 `verification intensity` 推进到 `information calibration`

### 2. 用于 PPT 的 `existing work / traditional view / gap`

这组文献特别适合支撑以下 PPT 结构：

- `existing work`
  现有自动化偏差和 decision aid 文献往往把风险理解为：用户看得少、查得少、核得少。

- `traditional view`
  传统解释默认：只要提高 verification intensity / search intensity，就能改善判断质量。

- `gap`
  但这仍没有回答一个更细的问题：用户到底是不是被保留了足够代表性的、冲突性的、可反驳的信息？

- `our move`
  因此，第一篇不把问题停留在 `less search`，而是推进到 `AI 是否改变了对 evidentiary sufficiency 与 additional evidence value 的判断`。

### 3. 用于批判最直接的靶子

如果后续只想抓一个最直接、最容易讲清楚的靶子，优先顺序建议是：

1. **Kupfer et al. (2023)**  
   因为它最接近 “少搜索 = 坏决策”。

2. **Seow (2011)**  
   因为它可以作为桥梁，帮助你把问题从“限制性设计”推进到“信息代表性与遗漏结构”。

3. **Lyell & Coiera (2017)**  
   因为它能支撑你批判 “verification complexity / vigilance” 还不够细。

## 给后续自己的提醒

- 不要把这些文献批判成“它们都错了”。
- 更稳的写法是：它们抓住了 `verification / reliance / search reduction` 的重要问题，但还没有把问题推进到 `AI summary 的信息代表性、冲突性与诊断性结构`。
- 第一篇最强的位置不是否认 automation bias 文献，而是说明：**它们还停留在行为强度层，而你要往信息结构层推进。**
