# TESTPROJECT → SocioVerse2 框架迁移方案（讨论稿）

日期：2026-10-17。状态：研究推导与迁移设计，未实施、未运行、未验证迁移结果。

## 1. 目标与已确认边界

目标是用 SocioVerse2 承载原稿的辟谣策略研究，保留概率抽样的行为逻辑。首阶段提供单事件过程、轨迹记录和干预分支比较。迁移本身不作为新的行为理论，也不宣称会提高模拟真实性。

明确确认的内容：

- 研究主线仍为辟谣时机、目标群体和政府可信度与信念转变的关系。
- 圈内用户为谣言源关注者；圈外为非关注者，不按实时信念重新分组。
- 相信和传播由概率抽样决定，不能由 LLM 输出覆盖抽样结果。
- 不增加共同评估人群、匹配、统一干预后观察窗口等设计；原稿 TBU 边界处理保留。
- 目前只形成方案，不修改现有代码，不开展真实模型调用。
- TESTPROJECT 保持独立于总项目的 Paper 1 研究基准。

前后讨论存在两处需要在最终定稿前处理的边界，不在本文擅自裁决：

1. 之前确认假设关注网络、排序和有限阅读，之后要求“全都按照原稿，将目标放在框架移植上”。因此本稿暂停增加排序实验，不将恢复二维空间或保留信息流任一项写成已获确认。框架把接触实现单独封装，以下分别注明原稿与现有代码的差异。
2. 之前明确确认转变比例与转变时间并列，且要求标注改动。后续收缩到原稿规则不能由助手擅自解释为取消该确认。故保留“转变比例”作为已讨论的新增结果项，但分母仍待定，暂不规定可执行公式。

这两点不阻碍确定模块职责和迁移路线，但阻止宣称方案已经完成规则等价性定义。

## 3. 迁移后的模块划分

官方架构使用 PopulationProvider、EnvironmentProvider、DecisionModel、MetricCollector 四接口，核心框架管理调度和记录；研究自身提供规则实现。规则型 DecisionModel 不要求 LLM。

来源：[SocioVerse2 官方架构](https://socioverse.fudan-disc.com/docs/concepts/architecture/)；[官方仓库](https://github.com/sii-research/SocioVerse2)。接口名称和职责已核对，本文提出的研究内部模块名不是上游已有 API。

```text
研究配置：事件、原稿参数、干预方案、随机种子
                   ↓
PopulationProvider：固定用户身份与群体
                   ↓
EnvironmentProvider：事件、接触过程、政府干预、世界状态
                   ↓
DecisionModel：PB→RC / GT→RF 概率抽样
                   ↓
EnvironmentProvider.apply：提交状态与传播后果
                   ↓
MetricCollector：原稿 TBU、状态人数及辅助过程量
                   ↓
SocioVerse2 轨迹存储 → 分支比较 → 单事件报告
```

### 3.1 人群模块

- 从现有本地资料建立固定 agent_id 和圈内外身份，复用资料导入、去重及来源记录能力。
- 原稿基准人数为圈内 82、圈外 500。现有画像可以保留作展示或追溯资料，但不能未经论证改变 PB、RC、GT、RF。
- 原稿按群体设定的概率与现有“画像→提示词→LLM 决策”是两种机制；后者退出本次核心行为路径。
- 谣言源和政府保持特殊发布／干预角色，不强行混成同一种普通用户。

### 3.2 环境与接触模块

- 环境拥有当前时间、用户状态、有效接触、传播内容及政府状态。
- 将“接触机会如何产生”单独实现为研究内部组件；输出接收者、发送者、时间、谣言／辟谣类别及可追溯标识。
- 同一个接触结果再送往概率决策模块，禁止“生成接触时已经抽一次接受，决策时再抽一次”。
- 原稿路线：二维位置、随机移动、圈内外活动范围和相遇。现有代码路线：关注、活跃、推荐及讨论曝光。二者不等价，不能仅改类名就称完成原稿复现。
- 官方框架的广播便利接口不自动代表全员接触；实际接触必须遵守研究规则。不能用默认广播覆盖原稿 In-out 的作用。
- 轮内更新顺序不能由框架默认值替原稿作研究判断。现有代码采用轮初冻结、轮末统一提交；如果最终采用的原稿规则需要顺序更新，必须单独标注这个差异。

### 3.3 概率决策模块

将现有 provider.decide 的核心行为角色替换为规则型 DecisionModel；原有 HTTP provider 可保留在历史代码中，但不参与本研究路径。

原稿谣言接触分支：

1. 对符合原稿适用状态的有效接触，以 PB 抽样决定是否相信。
2. 若相信，再以 RC 抽样决定是否成为传播者。
3. 结果分别为不相信、相信不传播、相信且传播。

原稿政府辟谣接触分支：

1. 以 GT 抽样决定是否接受政府辟谣。
2. 接受后转为不相信谣言，再以 RF 抽样决定是否转发纠正。
3. 不接受时保持原有信念。

保留原稿 RC=P×PB 的规则，明确它是为迁移保留的原稿假设，不把之前指出的证据不足写成已经解决。P 的精确比值与原稿近似值存在舍入差别，参数文件需记录实际采用值，避免无声改变。

每次抽样保存概率、随机值、规则名称和结果。随机性来自显式种子及可恢复的随机状态，不依赖运行目录或分支名称。现有 Mock 只用于软件测试，不可冒充上述概率模型。

连续的 0–100 belief_score、60/40 阈值和公开表达标签，不应硬套在原稿离散状态上。核心保存原稿状态；展示层确需兼容时使用明确标签，不伪造连续心理分数。

### 3.4 干预模块

- T_G 控制政府开始辟谣的时间。
- In-out 控制政府主要接触圈内、随机区域或圈外用户的规则。
- GT 为实际接触后的接受概率，不能继续使用现有“过去十条内容准确几条”的提示线索代替。
- RF 为接受后传播纠正的概率。
- 现有“单轮直接送给 40 人”的实现不是原稿政府持续移动接触的等价表达，必须在差异表中保留，不能直接复用为原稿策略。
- 同一研究版本中改变干预安排可组织为分支；改变人群、接触规则或行为模型，应作为新研究版本，不能冒充只改变干预的分支。

### 3.5 指标与报告模块

- 原稿 TBU：统计政府开始后、模拟结束前完成相信→不相信的用户，计算转变时间减 T_G 的平均值；原稿公式使用 T_i>T_G。
- 不引入共同评估人群、统一观察窗口等新增研究设计。无完成者时返回缺失及完成者人数 0，不填 0 表示立即成功。
- 现有 individual_tbu 使用发布前相信者集合、30 轮观察窗口，并允许当轮转变；这些不能直接当作原稿 TBU 复用。
- 转变比例保留为此前确认的新增指标，最终需明确分母；未定义前不产生貌似确定的“成功率”。人数、接触次数及传播次数可以先作为描述统计。
- 复用 HTML 时间轴和用户轨迹的展示思路，增加概率、抽样值和状态转换依据；不展示虚构的 LLM 理由。
- 报告同时显示模型版本、参数来源和完成状态。模型内的干预差异不表述为真实人群政策效果。

## 4. 现有代码的复用与必要改动

| 当前模块／行为 | 处理 | 原因 |
|---|---|---|
| import_data.py 与单事件 JSON | 复用文件解析与溯源，重新检查字段用途 | 避免重新准备已有资料 |
| core.initialize / apply_profiles | 拆入人群与环境初始化 | 去掉依靠提示词产生核心行为的耦合 |
| core.build_feed 与线程读取 | 隔离成现有接触实现参照 | 不能与原稿空间相遇混称同一机制 |
| core.step | 拆成观察、抽样、应用、测量 | 防止旧循环与框架循环各推进一次时间 |
| provider.py 的 HTTP／Mock | 不作为原稿概率行为实现 | 二者均不等于 PB→RC、GT→RF |
| runner.py 的父轨迹／分支组织 | 复用实验概念，映射框架版本／分支 | 不嵌套调用两个完整主循环 |
| storage.py 的快照、校验、失败标记 | 复用设计，适配框架存储 | 需要完整恢复随机状态和环境状态 |
| individual_tbu / summarize | 按原稿口径重新实现主要指标 | 当前统计边界与原稿有差异 |
| report.py | 复用时间轴与用户视图，改数据适配 | 展示概率规则的过程，而不是 LLM 推理 |

应保留现有两个项目目录，不覆盖历史结果。实施时先固定现有代码和依赖版本，再在独立 study 中组织新实现。具体落盘位置在实施阶段依项目目录规则确定，本稿不新建实现目录。

## 5. SocioVerse2 对接中必须防止的语义变化

框架按外部更新、观察、决策、应用、记录推进，初始状态为 step 0。分支前史依赖已存行动重放。[官方运行循环](https://socioverse.fudan-disc.com/docs/concepts/simulation-loop/)

本项目的适配要求：

- 源事件初始化、第一轮接触、T_G 发生轮必须有清楚的 tick 映射，不出现一轮偏移。
- 历史回放不重新抽取已发生的决策。环境运动等随机过程也必须可确定重建，不能只保存用户最终动作。
- 没有有效接触时保持状态，不为了每人每轮一条记录而触发新的相信抽样。
- 完整轨迹与行为记忆分开：规则模型的历史记录用于追溯，不自动作为改变概率的“记忆机制”。
- 失败时不能把半轮更新记成完成；恢复运行需要状态、时间、随机过程和干预进度一致。框架支持能力需实测，不直接沿用旧项目的保证。
- 优先采用原生 study 接口以支持分支。若原规则无法无损映射到原生回放，先保留独立重复运行的比较，不为了回放方便改变规则。

## 6. 后续实施顺序与验收方法

以下仅为将来实施路线，本轮不执行。

### 阶段 A：冻结规则对照

产出原稿—现有代码—目标方案逐项对照表；标识直接保留、修改、暂不采用和未明确。接触方式与新增比例指标定稿后，才允许称为完整规则合同。

### 阶段 B：拆出与框架无关的概率核心

先让有效接触输入能够得到原稿状态和行动输出。用固定随机数检查 PB、RC、GT、RF 各分支，验证无接触不更新、状态人数守恒、同一事件没有重复抽样。

### 阶段 C：实现四接口

核心规则保持同一份实现，分别由独立小运行器和 SocioVerse2 调用。以相同接触序列、初始状态与随机序列逐步比较，而不是拿旧版 LLM 曲线要求数值一致。

### 阶段 D：恢复单事件与干预比较

接入本地事件；先完成一个基准轨迹和一个干预分支，再覆盖时机、对象、GT 的配置组合。原稿参数集与现有 80 轮／TG10–50 参数集分开保存，不拼成一个无来源的新基准。

### 阶段 E：展示与研究交付

生成过程页面、每轮面板、干预比较和参数来源说明。概率抽样验收不要求得到预期政策结论；主要检查正确执行和可重复性。

最低验收场景：

1. PB=0 与 PB=1、RC=0 与 RC=1 的边界行为正确；GT、RF 同理。
2. 只有相信谣言后才执行对应 RC 分支，只有接受纠正后才执行 RF 分支。
3. 相同种子和配置重跑一致；修改运行名称不改变抽样轨迹。
4. 中断恢复与完整运行一致；分支前史一致且不重复抽样。
5. T_G 前后时间正确；无转变、部分转变、全部转变时 TBU 处理正确。
6. 接触生成器与决策器分开检查，不能用最终曲线相近掩盖不同微观规则。
7. 旧输出保持可识别，迁移结果带独立版本，不覆盖或伪装旧实验。

## 7. 迁移收益、代价与当前限制

**收益**：统一人群／环境／行为／指标接口，集中管理轨迹和实验版本，支持可追溯的干预比较；以后替换行为模型时可以明确隔离改动。

**代价**：现有程序轻量、领域定制；引入框架会增加依赖、类型适配和存储转换。规则对接中的时间顺序、随机过程和分支回放比类名重构更重要。

**不承诺的收益**：迁移本身不提供 PB、RC 等假设的理论支持，不证明空间或网络接触真实，不自动改善预测，也不产生论文创新。

目前已有资料足以形成上述框架方案，不要求用户重复提供源码。未明确项由现有文件继续核对，确实无法确认时在方案中留为缺口；不虚构“已经找到原稿完整实现”或“迁移已通过测试”。
