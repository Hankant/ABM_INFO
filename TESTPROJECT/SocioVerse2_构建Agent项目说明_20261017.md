# 给 SocioVerse2 构建 agent 的项目说明

## 一、项目委托

请为以下研究建立一个独立的 SocioVerse2 study，并按“环境 → 人群 → 推演 → 报告”逐阶段组织研究设计与构建。

**项目名称：不同圈内外条件下的政府辟谣策略与信念转变。**

本项目已有原始论文、两版 Python 实现、单事件数据及演示。目标是将已有研究迁入 SocioVerse2，优先保持原稿的研究问题和概率规则，不重新提出一套 LLM 社会行为理论。

本说明用于立项和阶段设计，不代表研究规则已经全部定稿，也不授权自动执行大规模实验、付费 API 调用或发布数据。可以先完成材料读取、研究规格草案与差异登记；遇到本文明确的待确认边界时，集中向研究者说明，不能自行补成事实。

## 二、研究问题

我们研究社交平台上的谣言传播与政府辟谣。用户分为谣言源的关注者与非关注者，两类用户在原稿设定中具有不同的谣言相信概率和接触条件。

**核心问题：在不同圈内外相信概率差异的条件下，政府辟谣的发布时间、目标群体与政府可信度，如何影响用户从相信谣言到不相信谣言的转变？**

具体比较：

1. 政府较早或较晚开始辟谣，信念转变过程有何不同？
2. 政府主要面向圈内用户、随机对象或圈外用户辟谣，结果有何不同？
3. 政府可信度不同时，结果有何不同？
4. 圈内外相信概率的差异，是否改变上述策略之间的比较结果？

分析对象是单个谣言事件中的模拟用户及其群体动态。先形成单事件的可追溯轨迹和干预比较，再考虑扩大实验；不要把全部历史事件和参数组合自动展开。

## 三、研究变量与解释边界

| 名称 | 本研究中的含义 | 模型位置 |
|---|---|---|
| 圈内／圈外 | 是否关注谣言源；不是当轮是否相信谣言 | 固定用户身份 |
| PB | 有效接触谣言后相信它的概率 | 个体状态转换规则 |
| RC | 已经相信的条件下，成为谣言传播者的概率 | 个体传播规则 |
| PBd | 原稿中圈内与圈外 PB 的差，即 PB_in−PB_out | 场景条件，用于比较策略在不同条件下的表现 |
| T_G | 政府开始辟谣的时间 | 干预时机 |
| In-out | 政府主要在圈内、随机区域或圈外开展辟谣 | 干预目标 |
| GT | 接触政府辟谣后接受它的概率 | 原稿对政府可信度的操作化 |
| RF | 接受辟谣后转发纠正信息的概率 | 纠正传播规则 |
| TBU | 政府开始辟谣后，完成相信→不相信转变者的平均等待时间 | 主要结果 |

这些定义来自原稿的方法设定，不表示各函数关系已获得独立经验验证。尤其保留 RC 与 PB 的绑定是为了遵循原稿，不意味着已解决其理论依据问题。PBd 不能被扩大解释为完整的信息茧房形成过程。

我们已讨论将“转变比例”与“转变时间”并列报告。转变比例属于相对原稿的新增项，其分母尚未定稿；请保留该项及改动标记，不自行定义成功率，也不自行删除。

## 四、必须保留的行为规则

### 4.1 谣言

对符合原稿适用状态的有效谣言接触，先以 PB 进行概率抽样；若相信，再以 RC 抽样决定是否传播。三个结果分别为：不相信、相信但不传播、相信并传播。

保留原稿关系 RC=P×PB，P 由原稿基准 RC 与 PB 得到。实际数值、舍入与边界以原稿表格和可核实实现为依据，记录其来源。

### 4.2 辟谣

政府从 T_G 开始辟谣，In-out 改变其目标范围。用户实际接触政府辟谣后，以 GT 抽样决定接受与否；接受则不再相信谣言，随后以 RF 抽样决定是否传播纠正信息。不接受则保持原信念。

**相信和传播由概率规则决定，不由 LLM 自由生成的信念分数或行动替代。** 不需要因为使用 SocioVerse2 就调用 LLM。构建 agent 是协助研究的工具，不等于被模拟的用户必须是 LLM agent。

重复接触、已拒绝者能否重新相信，以及普通用户转发的辟谣如何被接受，若现有材料没有明确规定，先登记缺口，不自行引入记忆强化、反转或阈值规则。

### 4.3 结果统计

沿用原稿 TBU：计算政府开始辟谣后完成转变者的 T_i−T_G 均值，原稿条件为 T_i>T_G；未完成者不进入该均值。没有完成者时报告缺失及人数，不填零。

研究者已明确不在本次迁移中展开共同评估人群、匹配或统一干预后观察窗口的重新设计。报告应解释原口径的含义，但不要借此扩大实施范围。

## 五、分阶段构建要求

### 阶段 1：环境

先读取原稿与现有代码，形成环境规格及差异表，至少包括谣言源、政府、时间、有效接触、信息传播和状态更新顺序。

这里存在需要显式处理的差异：原稿使用二维随机移动与相遇；现有单事件代码使用关注网络、活跃概率和信息流。前期讨论曾考虑重设计网络接触，随后研究者收缩为遵循原稿、优先框架迁移。**请把接触方式列为环境阶段的一项集中确认，不自动把空间相遇换成推荐信息流，也不把现有网络代码说成原稿的空间实现。**

目标是把接触生成放在 EnvironmentProvider，将接触后的概率判断交给 DecisionModel。暂不新增排序实验、动态取关、多层网络或其他理论机制。

阶段交付：环境规格、接触差异、时间映射、政府干预入口，以及真正无法从文件确定的问题清单。

### 阶段 2：人群

保留固定身份与圈内外划分。原稿基准为 82 名圈内用户和 500 名圈外用户。优先复用现有单事件资料，不依赖额外在线人群服务。

现有画像可用于记录和展示，不能未经确认成为 PB、RC 或 GT 的新决定因素。不要把本事件历史评论立场当作事前相信概率，不把被复制使用的画像当作同一个模拟身份，也不声称现有资料包含完整真实关注网络。

阶段交付：用户名册、状态与参数说明、画像字段用途及资料来源。

### 阶段 3：推演

建立规则型 DecisionModel，并使用 SocioVerse2 组织运行与干预比较。以独立配置表达 T_G、In-out、GT 和 PBd；保留原稿参数的含义，不混入现有 LLM 提示参数。

从一个事件、一组条件和一个比较分支起步。保存概率抽样、接触与状态转换，以便解释每个用户为什么发生变化。已有前史回放不应重新抽样；改变行为规则或接触规则应记为模型版本变化，而非纯干预分支。

先验证无接触不更新、条件抽样正确、状态守恒、种子可重复、恢复与回放一致。不要要求程序生成原稿预期的结论作为验收条件。只有在前面规格已确认后再进入构建与运行。

阶段交付：推演配置、规则实现说明、验证记录、单事件轨迹和干预比较数据。任何未运行环节明确标为未运行。

### 阶段 4：报告

报告回答核心辟谣策略问题，并呈现：

- 参数条件和结果口径；
- 各类状态人数随时间的变化；
- 原稿口径的 TBU 与完成转变人数；
- 转变比例：只有分母确认后才计算；
- 代表用户的接触、抽样、传播及转变轨迹；
- 策略间差异与随机重复的不确定性；
- 原稿、旧代码、新框架之间的改动表。

解释范围限定为模型内部结果。传播规模、转发行为或模拟信念变化，不自动代表真实人群的心理变化或政策效果。尚未运行时只交报告模板与分析计划，不生成模拟结果数字。
