# 环境纳入材料：模拟世界 E

版本：environment-material-v1，2026-10-18。  
适用研究：不同圈内外条件下的政府辟谣策略与信念转变。  
用途：直接上传至SocioVerse2的“环境构建／纳入环境的材料”。本文已包含必要场景、空间规则、事件内容和时间线，不要求读取其他本地文档。本文不是模拟用户收到的帖子，也不是已经通过运行验证的报告。

## 1. 给构建 agent 的任务

将本文转换为环境层、环境状态、政府启用事件和局部接触信息。目标是让现有Python承载方式与SocioVerse2承载同一模型，使用相同空间规则、初始快照与事件内容。

先采用本文已确认的空间基准；原有材料若仍称圈层随相信者人数变化，本阶段以本文的固定半径20为准。不要加载旧项目的关注流、推荐槽位、80轮时长或40人强制投送来补空间规则。

本文区分：已确认空间规则、原稿参数、供实施的时间接口建议，以及尚未确认的行为细节。可以直接建立环境规格、内容对象和配置；不得把未确认的行为规则写成用户已批准。

## 2. 模拟世界的含义

模拟一个谣言事件中的信息接触与政府纠正。普通用户582人，圈内82人、圈外500人。圈内外身份表示是否关注谣言源，在本版本中固定，不因位置跨圈或信念变化而重新分组。

二维坐标是抽象接触环境，不是真实地图。距离和tick均为模拟单位，不转换为米、分钟或日期。空间接触表示有机会接收信息，不等于相信或转发。

谣言源与政府为特殊角色，不计入582名普通用户。模拟用户使用共同概率规则，不需要调用LLM生成人格、信念或行动。

## 3. 六个环境层的内容

下列层名是本研究的配置名称，不代表已经存在可执行实现。physical表示世界或环境控制量；information表示信息内容。

| 层名 | modality / scope / dynamics | 纳入的内容 | 排除的内容 |
|---|---|---|---|
| world_geometry | physical / macro / static | 正方形世界、坐标范围、距离单位、边界反射规则 | 现实地理、未经确认的道路或设施 |
| circle_state | physical / macro / static | 圆心(0,0)、固定半径20、区域判定 | 随信念变化的半径函数；本阶段不能标endogenous |
| contact_state | physical / local / endogenous | 当前位置、有效接触、发送者与接收者、信息类别与来源角色 | 直接判定用户相信或传播 |
| government_policy | physical / macro / scheduled | T_G、In-out、GT、政府启用状态、活动区域 | 默认全员曝光、用GT改变几何距离 |
| rumor_content | information / local / static | 主张ID、原始文本、源ID、来源状态 | 把主张真实性或全体用户信念公开给每个用户 |
| correction_content | information / local / scheduled | 纠正ID、文本、实验脚本标记、启用后可传播状态 | 冒充已核验官方证据；在T_G前让用户看到纠正 |

circle_state是静态几何，但用户位置是动态的。可将位置作为provider内部世界状态或contact_state的底层数据，不要因用户移动而把圆半径改为动态。

宏观层保存政策，不表示普通用户能读取未来政策时间表。环境内部、审计日志和用户实际观察必须分开。

## 4. 已确认的空间配置

| 配置 | 值 |
|---|---|
| 世界 | x、y均在[-50,50]，正方形100×100 |
| 圈层 | 圆心(0,0)，固定半径20 |
| 谣言源 | 固定(0,0)，不移动，持续具备谣言发送资格 |
| 圈内初始位置 | 圆内按面积均匀抽样 |
| 圈外初始位置 | 正方形内、圆外区域均匀抽样 |
| 用户运动 | 每tick独立均匀抽取[0,2π)方向，步长2 |
| 政府运动 | T_G起每tick独立均匀抽取方向，步长1 |
| 圈内用户边界 | 圆边界反射，只在圆内活动 |
| 圈外用户边界 | 可以穿圆，只在正方形外边界反射 |
| 信息接触 | 移动结束后，接收者与有效发送者距离≤2 |
| 路径中途接触 | 不计算；只检测移动后终点 |
| 接触去重 | 每个有向发送者—接收者对每tick最多一条接触 |

圆内面积均匀抽样：独立取u,v∈[0,1)，theta=2πu，r=20√v，位置为(r cos theta,r sin theta)。圆外初态：在正方形均匀抽坐标，落入x²+y²≤400则重抽。

政府在tick 0生成并保存位置。In-out=2时在圆内初始化且只在圆内移动；In-out=1时在整个正方形初始化并可穿圆；In-out=0时在圆外区域初始化，只能在正方形减去圆内部的区域移动。

圈外政府碰到圆边界须反射，圈外普通用户可以穿过圆。政府是否接触某用户依据距离和有效状态，不额外按用户身份过滤，也不把圈边界设成阻挡信息的墙。

### 边界实现要求

计算本tick运动路径上的最近边界交点，走到交点后镜面反射，再走完剩余距离。允许连续碰撞，不能将越界终点直接投影回圆或截断在边界。

圈外政府须检测圆形障碍及四条世界边界。路径可能穿过圆后终点仍在圆外，因此不能只检查最终坐标是否合法。

最小验收例：圈内用户从(19,0)向右走2，结果为(19,0)；圈外政府从(20.5,0)向左走1，结果为(20.5,0)；圈外普通用户同样运动则到(19.5,0)。边界测试未通过不得标注空间实现已验证。

## 5. 纳入的信息对象：直接使用以下内容

### 5.1 谣言对象

```json
{
  "event_id": "event_052",
  "claim_id": "claim_event_052",
  "content_id": "event_052:rumor",
  "source_role": "rumor_source",
  "content_kind": "rumor",
  "text": "近日，辽宁一名扶贫干部怒斥一对懒惰父子的视频引发热议。视频中，这对父子家里地面上垃圾遍地，尿桶就被他们放在床边，父子俩每天睡到自然醒，不干活，自家的牛被饿死了都不知道。。。",
  "provenance": "source_workbook_post_text_imported_by_existing_project",
  "claim_review_status": "requires_content_review"
}
```

以上为待核实主张的已有记录，文本中的评价不代表本材料认定的事实。它是从既有事件数据提取的共同内容，不是未经加工的原始采集文件。

### 5.2 纠正对象

```json
{
  "event_id": "event_052",
  "claim_id": "claim_event_052",
  "content_id": "event_052:correction",
  "source_role": "government",
  "content_kind": "correction",
  "text": "针对网上流传的“近日，辽宁一名扶贫干部怒斥一对懒惰父子的视频引发热议。视频中，这对父子家里地面上垃圾遍地，尿桶就被他们放在床边，父子俩每天睡到自然醒，不干活，自家的牛被饿死了都不知道。。。”，本账号澄清：这一说法不属实。请勿继续传播未经核实的信息。",
  "correction_mode": "scripted_no_evidence",
  "correction_origin": "experimental_script",
  "correction_status": "experimental_script_not_verified_official",
  "evidence_text": "",
  "evidence_status": "not_provided"
}
```

纠正对象可以预存于环境内部，但T_G前不得成为用户可见内容。完整事件对象、证据状态和未来政策表只供调度、审计使用。普通用户转发纠正时保留原content_id，并将直接发送者角色标成peer，不能仍记成government直接接触。

没有真实官方纠正证据可纳入，不补造引文或权威背书。文本不用于重新估计PB、RC、GT或RF。

## 6. 事件与广播时间线

政府启用使用定时环境事件；空间接触负责投递信息。不要为了填满界面的广播栏而增加全员广播。

| 时点 | 环境变化 | 用户可见信息 |
|---|---|---|
| 初始化 | 创建世界、固定圈层、用户身份与坐标、源与政府角色；内部登记两种内容 | 不因登记内容而自动全员曝光 |
| T_G之前的更新tick | 用户移动，源和具备资格的用户产生局部谣言接触；政府不移动、不纠正 | 仅实际有效接触到的信息 |
| T_G当tick | 政府启用，开始本轮移动和局部纠正接触 | 只有实际接触政府或符合共同规则的传播者才看到纠正 |
| T_G之后 | 用户与政府按各自区域继续移动，环境依据状态与传播资格生成接触 | 局部传播，不增加持续全员强制投送 |
| tick 250 | 不因LC=250自动删除内容、停止源或重置用户状态 | 不发生无依据的失效变化 |
| tick 400更新后 | 停止推进，保存完整终态和日志 | 不自动延长到所有用户都完成转变 |

LC=250是原稿首末评论时间跨度的校准记录，未查到可直接执行的硬失效算法。当前不得将其当作帖子TTL。该解释不等于已证明生命周期对现实传播无作用。

### 具体T_G尚未选择时

可以保留事件模板和“待实例化”状态，但不能将空scheduled_events解释为已确认无干预。若接收study中已有研究者确认的条件，使用该条件；否则列出一次运行条件缺口。

以下仅是T_G=20的启用事件示例，**不是已经批准的新运行条件**：

```json
{
  "at_step": 20,
  "target_layer": "government_policy",
  "op": "set",
  "selector": {},
  "property_name": "enabled",
  "value": 1,
  "note": "Enable government movement and contact-based correction; do not broadcast to all users."
}
```

事件字段须按接收端安装版本验证，provider还必须实际实现enabled属性含义。只有JSON能解析不能证明干预能执行。

本空间模式的 `information_program.broadcasts` 可保持空数组。定时事件使政府具备纠正能力，接触记录才决定具体接收者。

## 7. 逐tick环境与决策接口

以下是建议的同步接口顺序，供构建agent落实前与接收study的共同规则合同核对；它不是本轮对先前全部行为建议的追加批准。

```text
读取上一tick已提交状态与传播资格
→ 应用本tick定时启用事件
→ 移动用户和已启用政府
→ 按终点距离生成接触
→ 向DecisionModel提供有效观察
→ 收集并验证动作
→ 统一提交状态和传播资格
→ 保存本tick日志与快照
```

世界时间只能由一个调度器推进。observe_batch只读，不重复移动或抽样。若采用此同步顺序，本tick新增普通传播者从下一tick开始影响别人；两框架须一致。

接触记录至少包括：tick、contact_id、sender_id、receiver_id、source_role、content_id、content_kind、distance、接触判据版本。不能把有接触直接等同于接受。

### 与行为层的边界

原稿明确的行为合同是：S有效接触谣言后PB失败→R；PB成功后RC失败→E、RC成功→I。政府纠正GT失败保持信念，成功则不再相信，并以RF决定纠正传播。这些由DecisionModel执行，环境负责提交其结果。

以下仍属先前建议而非本轮自动确认：普通用户全S初态；每tick只处理一次适用接触；纠正优先；R不可逆；同伴纠正沿用GT；首次接受纠正时只抽一次RF。接收agent若无明确确认，必须把它们与已经确认的空间值分开记录。

## 10. 环境阶段的交付和状态展示

接收agent应完成：

1. 六层配置，其中circle_state为static。
2. 两个内容对象及来源状态，保持纠正内容的实验性质。
3. 有确认运行条件时实例化政府启用事件；没有时保留明确待实例化状态。
4. 空间provider的几何、角色区域、移动与接触职责；实现存在时检查实际注册名称与配置一致。
5. 初始位置与单步反射的可检查输出、接触样例表、边界测试记录。
6. 分别报告：schema是否通过、provider是否可加载、边界是否测试通过、行为合同是否就绪、是否实际运行、双框架是否等价。

无需添加真实地图、外部新闻、人群池、推荐算法、天气或新的现实政策事件。本阶段的环境已经足够具体，重点是按确认规则执行和验证，而不是增加环境层数量。

只凭页面显示六个层或“完成”不能宣称运行成功。存在已知边界实现问题时，保留失败／未验证状态，并按修复后的版本重新生成受影响的轨迹。

## 11. 双框架共同起点

在同一运行条件下，初始位置和完整状态只生成一次，两框架加载同一快照；固定内容、参数、用户ID、角色、空间规则及输入哈希。仅使用相同seed不够，移动与行为随机值还需要共同分配合同。

先比较位置，再比较接触，再比较动作和状态。不得使用不同接触机制或行为模型却将差异归因于框架。

当前本文提供的是可纳入环境的研究材料和接口要求。实际源码、初态完善、待确认规则和测试仍须在接收端完成，不伪称已经替对方执行。
