# V3 用户身份表：使用说明

日期：2026-10-18。已从现有输入整理，未重新抽样，未运行模拟。

## 1. 直接使用哪个文件

将 [用户身份表.csv](./用户身份表.csv) 与本文交给 SocioVerse2 构建 agent。表中一行是一名模拟用户，共582行；SOURCE和GOVERNMENT不属于这582名普通用户。

[来源与核查.json](./来源与核查.json) 保存输入来源、SHA-256和核查结果，供追溯，不属于普通用户的提示词。

CSV采用UTF-8 BOM编码，字段名用英文便于程序读取。它是由已有名册整理的共同身份输入，**不是582名真人的观测数据，也不是已完成的个人画像**。

## 2. 各列是什么意思

| 列 | 中文含义 | 如何使用 |
|---|---|---|
| agent_id | 模拟用户唯一ID | 按字符串读取，原样保留；不得重新编号 |
| group | 原有分组 | inside=关注原帖发布者；outside=不关注原帖发布者；V3中不表示空间位置 |
| follows_source | 是否关注原帖发布者 | 仅有true／false字符串；导入时显式转换为布尔值，不用字符串真假直接判断 |
| source_account_id | 关联的原始账户ID | 本次全部为空，表示没有建立可核查的逐人关联；不能以agent_id冒充真人账号 |
| population_origin | 用户名册性质 | rule_defined_synthetic_population=按规则设置的合成人群 |
| group_origin | 分组性质 | experimental_assignment=实验设定的分组，不是本次从真实关注关系中测得 |
| identity_source_record | 来源身份文件中的记录键 | 等于原文件中的agent_id，可据此定位；不是另一种真人标识 |

空的source_account_id统一解析为缺失值，不填0、不随机分配账户、不凭顺序连接其他资料表。

## 3. 这次确认了什么

- 582条记录、582个唯一ID，没有重复模拟ID。
- 82名inside用户，500名outside用户。
- follows_source与分组逐行一致。
- 与共同输入包逐行核对，未改变ID、顺序、分组或关注标记。
- 与更早的名册交叉核对，身份信息一致，582条donor_id全部为null。
- 来源中的582个initial_state仍全部未定。本表不设置初始信念，不把它默认为S或不相信。

因此，当前不能说“这582人对应305名真实账户资料的重复抽样”。旧资料库虽有独立的资料供体文件，但本次核查的名册没有建立逐人供体关联，无法据此统计谁重复借用了哪份资料。本表也不重新建立这种关联。

## 4. 构建agent具体要做什么

1. 读取CSV，核对582条、ID唯一、82／500分组及布尔字段。
2. 按每行创建一个模拟用户，保留原ID与分组。A/B/C/D实验均复用同一张身份表。
3. follows_source可用于建立用户到SOURCE的关注关系；这不意味着马上展示原帖，更不意味着用户相信原帖。
4. 不从group推断年龄、信任、相信概率或转发习惯；不要自动调用人群池补人。
5. 用户之间的关注关系另行确定，本表未提供这些边，不能擅自生成后称为原始关系。
6. 个人资料表和模拟经历表以后通过agent_id关联。本次没有生成个人故事、没有导入历史评论、没有初始化信念。
7. 若平台要求当前缺失的字段，列明要求和缺失情况；身份导入成功不等于整个模型已经可运行。

## 5. 来源与加工边界

主来源为 [共同输入包中的身份文件](../同模型双框架_最小共同输入包/inputs/population_identity.jsonl)。来源性质可对照 [共同输入包溯源记录](../同模型双框架_最小共同输入包/PROVENANCE.json)。本次还核对了旧交接内容中的population_roster_draft.jsonl，其相对路径与哈希保存在核查JSON中；该文件仅作溯源，不作为V3的行为输入。

本次加工仅将既有身份字段整理成CSV、增加空的原始账户关联列及来源记录键。未改动旧文件，未导入模拟输出。即使作为V3的起始输入，它仍是合成名册的整理版，不能重新标注为真实平台原始采集数据。

下一步需要另做个人资料字段及来源表：先检查哪些信息确实有依据，再决定缺失项是否采用明确的实验假设。当前身份表可以直接作为那一步的固定用户索引。
