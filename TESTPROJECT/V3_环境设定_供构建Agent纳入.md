# V3 环境设定：网络接触、LLM 决策与个人记忆

日期：2026-10-18。状态：供研究者审阅的设计草案；未实现、未运行。

## 1. 给构建 agent 的任务与版本边界

建立独立的 V3 环境草案，用网络决定用户能接触哪些内容，用 LLM 根据个人资料、实际观察和允许读取的个人记忆生成判断与行动。当前任务只准备研究材料和配置草案，不启动模型调用、不生成模拟结果。

本研究属于独立的 TESTPROJECT。V3 不覆盖此前“二维空间＋概率规则”的共同基准，也不等同于同模型的框架迁移。此前的圆边界、位置、速度、距离阈值和反射规则不进入 V3 网络环境。

本文包含环境所需的规则说明；配套验证结构见 [V3 最小验证与结构调整](./V3_SocioVerse2结构调整与最小验证.md)。全文字段为研究设计合同，不是可直接提交的 SocioVerse2 官方配置格式。构建 agent 应按部署版本的实际 schema 转换，不能仅创建 provider 名称就报告已经实现。

### 证据与决策状态

| 状态 | 内容 |
|---|---|
| 用户提出的 V3 方向 | 网络连接替代空间相遇；LLM 决定相信、评论和转发；保存个人记忆；关注者与非关注者区分；政府可以优先触达不同群体 |

建议规则可以物化为标记为 draft 的配置，但未确定项不得通过默认值伪装成已确认规则。先完成可准备的工作，最后集中输出一张缺项表。

## 2. 研究对象与环境中存在什么

环境表示单个事件在模拟社交平台中的传播过程。包含普通用户、原始信息发布者、政府纠正账号、关注关系、帖子、评论、转发、信息展示记录和干预时间线。

“圈内／圈外”在 V3 中仅作为旧称：实际字段使用“是否关注初始信息发布者”。它不代表物理位置、智力、轻信程度或既定信念。用户不会因为相信或不相信而自动换组。

网络连接提供候选信息通道；进入候选集、实际展示、相信、评论、转发分别记录。不得把有边直接算为看过，把展示直接算为相信。

环境只模拟已明确实现的展示规则，不声称复刻微博推荐算法。不用“内部连接密集”直接定义或证明信息茧房。

## 3. 环境层

以下名称为本项目拟议组件，不是已经注册的上游 provider。

| 层 | 保存的内容 | 变化方式 | 普通用户可见范围 |
|---|---|---|---|
| social_network | 固定用户ID、关注边、群体标签 | 首版建议运行中固定 | 自己相关的来源关系；不公开全图 |
| content_store | 原帖、纠正、评论、转发及其时间和关联ID | 原帖与纠正按排程，用户内容由行动生成 | 仅实际展示的内容 |
| exposure_state | 候选集、排序、阅读名额、实际观察包 | 每步更新 | 自己本轮实际展示内容 |
| government_policy | 发布时间、目标选择、投放预算、实际投放记录 | 按排程激活 | 被展示的纠正；不提供未来计划 |
| public_feedback | 已发布评论、公开互动计数 | 提交行动后更新 | 显式展示的评论与计数 |
| private_agent_state | 当前判断、个人历史、角色版本 | 每步提交后更新 | 仅本人允许读取的部分 |

private_agent_state 是研究内部状态，不能作为面向所有人的公共环境层广播。完整审计记录与 agent 输入分离保存。

## 4. 网络和接触规则

### 4.1 关注边

约定 follow(follower, author) 表示前者关注后者；信息候选方向为 author → follower。不要把关注方向误作信息传播方向。

若沿用旧人群，则82名关注者具有到 SOURCE 的关注边，500名非关注者没有这条初始关注边。是否允许非关注者通过其他渠道看到 SOURCE，必须由明确的转发或投放规则决定。

普通用户之间的群内边和跨群边另行生成并冻结。保存实际边表、生成参数和哈希，不能只保存“密集／稀疏”标签。暂不自动取关、关注或依据意见重连。

关注关系不等于对来源的信任。用户角色中对来源的既往评价须单独记录，不依据所属群体自动生成“高信任／低信任”。

### 4.2 候选内容与展示

建议首版候选来源为：关注账号的有效帖子、关注账号发布的转发、符合政策选择的政府纠正。推荐算法暂不另设一个隐含入口。

建议按发布时间降序排序，同时间按 content_id 稳定排序；截取确定的阅读上限。排序与阅读上限在四个验证组保持一致。活跃规则、内容有效期、是否重复展示尚待填写；不得沿用旧版 LC=250 作为新帖子的默认寿命。

同一原帖的多次转发，应同时保留原始 claim_id、转发者和转发记录ID。是否合并成一个展示卡片必须明示。不同来源带来的重复展示不应被无记录地吞掉，也不应自动等同于多次独立相信抽样。

评论仅来自当前允许观察的帖子下已发布的评论。评论选择规则及条数上限独立配置；首版建议时间排序，不按支持／反对立场挑选。

每次观察保存：agent_id、tick、展示内容ID与顺序、可见评论ID、来源显示信息和观察包哈希。没有新展示时，首版建议保持状态并不调用 LLM；如果允许离线反思，应作为另一个明确实验条件。

### 4.3 可见信息边界

不得给普通 agent 输入以下内容：研究者的真假标签、其他用户私有判断、全体相信比例、未发布或未看到的评论、未来纠正、实验组名及预期结果。

如展示评论支持比例，分母必须是该用户实际可见且已编码的评论，名称写“可见评论支持比例”，不能写成“大家相信的比例”。首版建议直接提供评论文本，不额外注入统计摘要。点赞与转发数量不解释为相信人数。

## 5. 信息材料与真实性边界

当前材料未提供可核验的真实官方纠正。下面只内嵌已有工程样例，避免构建 agent 重新寻找文件；它不是正式验证数据。

| 字段 | 样例内容 |
|---|---|
| event_id | event_052 |
| claim_id | claim_event_052 |
| 原帖文本 | 近日，辽宁一名扶贫干部怒斥一对懒惰父子的视频引发热议。视频中，这对父子家里地面上垃圾遍地，尿桶就被他们放在床边，父子俩每天睡到自然醒，不干活，自家的牛被饿死了都不知道。。。 |
| 来源状态 | 既有项目从事件表导入的文本；本次未完成原始事件事实核查 |
| 纠正样例 | 针对网上流传的上述说法，本账号澄清：这一说法不属实。请勿继续传播未经核实的信息。 |
| 纠正样例状态 | scripted_no_evidence；实验脚本；无独立证据；此处为缩写样例，不是旧版纠正文本的逐字副本 |

若使用此样例，须命名为工程或假设情景测试，不能报告为真实官方辟谣效果。正式实验应冻结确切原帖、纠正全文、来源、证据与发布时间。所有对照组读取相同字节的文本，不由各组临时生成。

“rumor／correction”等类型供程序与审计使用。输入普通 agent 时采用“帖子／回应”等中性字段；官方账号身份可以如实呈现，研究者的真伪裁定不进入用户观察。

## 6. 政府干预

保留原研究关注的发布时间与目标群体比较方向；具体实现改为网络中的内容投放，不再模拟政府移动。

| 事项 | 建议规则 |
|---|---|
| 发布时间 | 在 T_G 的观察阶段之前将纠正加入可用内容 |
| 目标分配 | 优先关注者／全体中随机选择／优先非关注者；暂不用高、中、低定义效果好坏 |
| 预算 | 每次目标名额 B、投放次数与预算口径固定，各策略保持一致 |
| 选择 | 群体内随机、不放回选择；群体不足时补齐或停止的规则待明确 |
| 展示 | 投放进入指定通道；是否保证阅读必须单独配置，不能默认全员可见 |
| 社交关系 | 定向投放不自动生成用户关注政府的永久边 |
| 接受 | 由决策模型根据实际观察生成，不在环境层先行设定 |

全体随机选择不是两群体各占一半。沿用82/500时，全体均匀抽取的关注者预期占比为82/582。

GT 若在 V3 中改为用户对政府的既往经历或来源线索，就不再是“接受概率”。须记录具体操纵文本及来源，另命名字段，禁止把 GT=0.6 翻译成“60%接受”后又要求 LLM 自主判断。首轮最小验证建议固定这部分，不与角色、记忆同时扫描。

## 7. 初态与逐步时间线（建议协议）

| 时点 | 环境操作 | 用户行为 |
|---|---|---|
| tick 0 | 加载冻结人群、网络、内容与排程；记录初态 | 不移动、不决策；不凭关注身份设置相信 |
| 发布步 | 加入 SOURCE 原帖 | 经候选与展示规则后才允许观察 |
| 每个 tick 开始 | 处理到时发布与政府投放；生成本步环境快照 | 尚未提交本轮行为 |
| 观察阶段 | 从同一快照生成各用户观察包 | 看不到其他用户本轮尚未提交的回答 |
| 决策阶段 | 环境不替用户判定 | 一次输出判断、评论、转发意向 |
| 提交阶段 | 校验后统一更新状态、生成评论与转发 | 本轮新增内容建议从下一步可见 |
| 记录阶段 | 保存观察、行动、状态、记忆和指标 | 仅本人已见信息进入个人记忆 |
| 结束步 H | 输出完整轨迹与未完成状态 | 不强制结束时改变信念 |

建议初始 exposure_status=unexposed；belief=not_assessed 表示未评估，不表示已拒绝。是否已有事前接触者须独立提供数据。若采用这个建议，必须在版本变更表注明与原稿初态的关系。

T_G、H、原帖发布步及时间单位尚未确定。不把图中第2／5／8轮示例自动当成正式实验条件，也不把旧400 tick自动映射成400次LLM调用。

## 8. 与行为、记忆的接口

环境传给决策模型的是当前观察，不包含预期结论。建议输出字段：belief（believe／uncertain／reject）、comment_text、repost_target_id、可选转发附言、引用的观察内容ID。评论与转发可以同时发生；不相信也可以转发质疑。

每个 agent 每步产生一个结构化决策记录，其中可含多个行动字段；实际映射到上游 Action 时由适配层处理。无接触、拒答、解析失败与“不相信”必须使用不同状态，不能失败后自动记为不相信。

完整历史始终保存，但决策是否能读取历史由实验条件控制。无记忆组不能从模型会话、缓存、上一轮摘要或重复的角色文本中偷偷得到历史。记忆组只读取本人已接触的信息和自己的判断／行动，不能读取全局日志。

记忆条数、截断方式与检索规则冻结并记录。模型生成的摘要不能覆盖原始记录，新增事实须能够追溯到已有记录。

## 9. 工程验收与缺项交付

必须能检查：边方向正确；未关注者无自动直达；没有未来信息；政府发布不等于全员阅读；同轮新评论不可被提前读取；同一内容不重复计数；私有信念不外泄；无记忆组输入不含历史；快照恢复后观察与状态一致。

构建 agent 交付：环境层说明、字段映射、待实现provider清单、候选网络与排程配置、来源登记、缺项表及静态校验结果。只有实际实现并通过测试后才能标记“可运行”。

缺项表至少包含：固定人群是否沿用82/500、网络边与生成规则、初始判断、原帖与纠正正式材料、T_G与H、预算与目标不足处理、活跃与展示规则、记忆设置、模型版本、随机种子与重复次数。不得为消除 null 而臆造。

| 旧版 | V3草案 | 性质 |
|---|---|---|
| 100×100空间、圆半径20、随机移动与反射 | 有向关注网络与信息展示 | 更换接触模型 |

| 传播资格／状态 | 增加评论、转发附言、不确定和个人记忆 | 扩展模型状态与行动 |
