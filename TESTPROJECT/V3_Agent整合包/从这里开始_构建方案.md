## 2. 真实账户和模拟用户怎样结合

305个账户与582个模拟用户不是一一对应关系。采用以下可查看、可撤回的方案，而不是假装它们本来就是同一批人：

1. 沿用582个模拟ID，关注者82名、非关注者500名不变。
2. 从原Excel按账户ID去重，得到305份账户资料，以P0001等编号表示。
3. 让每一份资料至少用于一个模拟用户，再重复使用277份，得到582个资料位置。
4. 按固定哈希排序把资料位置分配给模拟ID；分配不读取圈内外、评论立场或转发结果。
5. 每行明确记录profile_ref和profile_reuse_count。因此可以查出两个用户是否使用了同一份资料。

结果是277份资料各使用两次，28份使用一次。这是实验资料分配，不是从真实总体随机抽取582人的结果，也不是原始账户关注关系的恢复。该方法在核查记录中完整写明，便于复现；它尚未被确定为正式实验的人群生成规则。

为什么这样做：保留已有582人基准，同时让真实账户属性进入V3。代价是资料重复、人群属性分布可能偏离305账户的原始分布，且305账户本身只覆盖参与评论或转发者。两名借用同一资料的模拟用户不算两名独立真人，也不能保证两者在相同观察下有不同判断。

如果研究要验证“这305个账户当时如何反应”，应另做305人逐账户验证设计，不把该实验和582人合成传播实验混成一个结果。当前材料仍保留305份独立资料，未来可以使用，不需要重读原Excel。

## 3. 哪些真实资料已经进入自然语言

当前可用字段为：账户显示的性别、所在地、关注数量、粉丝数量、累计发博数量。它们被逐项写成文字，不自动翻译成性格或信任判断。

例如，程序会写“账户粉丝数量：1140”，不会写“你很有影响力，所以喜欢转发”。也不会根据所在地推断政治态度或相信程度。

原表未提供年龄、职业、对博主或政府的既往信任、一般分享习惯。因此这些字段保留为未知，不编出“35岁”“长期信任政府”等设定。这些用户已经可以形成自然语言输入，但其异质性主要是已观察的账户属性，尚不足以声称获得了经验证的心理差异。

当前还存在两类质量处理：

- 一份账户资料的累计发博数在两次记录中为16778和16779。两值均保留；初始prompt暂不采用该字段，不自行选其中一个。
- 六份不同账户资料的性别、所在地及三个数量完全一致。不能断言一定错误，但需检查采集或复制问题。这六份的这些属性均暂不进入prompt，不删用户、不补新值。

此外，所有账户资料的采集时点尚未确认早于事件。因此当前prompt是使用观测快照的探索性版本，不能直接报告为严格的事前预测。

## 4. 每次调用怎样拼接

人群模块先读582行。每个agent保存自己的agent_id、group、follows_source和persona_text。初始信念暂未设定，个人模拟经历为空。

每轮只有当环境确认某人需要决策时，才按下面顺序形成完整输入：

```text
固定任务说明
    ＋
此用户的persona_text（已写好，不能每轮重新随机生成人设）
    ＋
环境实际给此人展示的原帖／回应／评论
    ＋
此人在本次运行以前实际看到什么、怎么判断、做过什么
    ↓
LLM输出相信／不确定／不相信，以及评论、转发
    ↓
校验输出 → 提交状态和公开行动 → 保存此人的经历
```

首次调用没有模拟经历，不把原Excel中这个人后来发表的评论填进去。本事件真实评论默认留在验证资料中；如果以后用于历史回放，必须限定到可见时间，且不再把同一条已提供评论当作未见测试答案。

动态内容必须由环境模块提供。示例文件假设某用户看到原帖，只为演示输入格式，不是规定所有用户第1轮都收到原帖。原帖不是真假已被本包核验的事实陈述。

模型输出的结构举例仅说明字段，不预设应回答的结果：

```json
{
  "belief": "uncertain",
  "comment": {"enabled": false, "text": ""},
  "repost": {"enabled": false, "target_content_id": null, "text": ""},
  "evidence_ids": ["P001"]
}
```

程序检查belief取值、评论与转发字段、引用ID是否实际可见。不评论时文本为空；不转发时目标为空。解析失败记录为失败，不当成“不相信”，也不自动改用概率抽样。重试不得重复发布行动。

“相信”和“是否转发”分别保存，允许不相信却转发质疑。不要用“已转发”反推用户相信。

## 5. SocioVerse2中分别改哪里

官方架构将研究拆成人群、环境、决策和指标四个接口；以下是本研究的适配方案，不是宣称这些文件已经符合官方Persona或Action的schema。[官方架构](https://socioverse.fudan-disc.com/docs/concepts/architecture/)

| 模块／接口 | 交给它的内容 | 必须实现的操作 |
|---|---|---|
| 目标人群／PopulationProvider | 582行分配草案 | 保留ID；读入对应persona_text；映射为平台Persona；不重抽人 |
| 环境／EnvironmentProvider | 网络、原帖、回应、排程 | 产生每人的实际观察；保留真实发布顺序；不把研究者标签传给用户 |
| 决策／DecisionModel | 模板、此人资料、当前观察、本人记忆 | 按固定顺序拼接，调用同一指定LLM，解析并映射为平台Action |
| 记忆与记录 | 本轮观察、判断和行动 | 保存原始记录；只将该用户允许读取的部分提供到下一轮 |
| 指标／MetricCollector | 提交后的判断与行动 | 分开统计相信、不确定、评论、转发和失败，不依据人设推断结果 |

建议将判断与公开行动一起存入结构化结果，适配到平台“一名用户一个Action”时把评论、转发作为结果的子字段处理；具体实现须核对部署版本。

平台原有记忆功能如果自动把旧对话加入模型，必须检查真实调用内容；不能只设置一个memory=false字段就认为历史已经屏蔽。

## 6. 同一套资料如何用于B/C/D验证

三种设置使用同一批ID、相同网络和相同模型。实验代码切换哪些段进入模型，而不是生成三批人。

| 设置 | 传给LLM |
|---|---|
| B：不提供账户属性差异 | 共同任务＋用户ID及实验关注关系＋当前观察 |
| C：提供账户属性差异 | 共同任务＋完整persona_text＋当前观察 |
| D：账户属性差异加记忆 | C的全部内容＋本人此前模拟经历 |

这里明确控制了之前容易混淆的地方：实验关注关系在B/C/D中都保留；C比B增加的是账户属性，不是同时增加关注关系。B仍可因网络和观察不同而产生不同反应。

账户资料分配、属性隐藏规则和模板文本在三组间冻结。D使用自己本次运行形成的经历，不继承C的结果。先给三组相同外部观察序列检查决策，再允许评论和转发改变下一轮内容。

A仍可保留原概率规则作参照，但不是个人资料效果的唯一基准；C−B和D−C才分别对应本方案中新增的属性输入和模拟历史输入。若后续加入有来源的信任／习惯资料，应升级模板版本并重新核查对照差异。

## 7. 直接交给构建agent的操作指令

> 在现有研究中新增独立V3草案，不覆盖旧空间概率基准。先读取本说明、数据使用边界、582行用户分配草案和prompt模板。核对每个profile_ref均能找到305份资料中的对应记录。
>
> 不重新生成人群，不修改82／500分组，不把资料编号视为真人身份，不将未知信任或习惯自动补齐。profile_assignment为待确认的实验草案，正式运行前报告其重复使用结构。
>
> 先为两名用户显示完整调用输入，分别展示有记忆和无记忆的差别；记忆样例标明是演示，不写入初态。确认后把读取资料、观察、拼接、校验、提交和记录接到研究层接口。
>
> 初始信念、网络边、活跃过程、阅读上限、政府纠正材料、发布时间、记忆长度、模型与调用预算继续沿用已确认配置；没有确认的项目列出缺项，不用默认值补造。当前草案的runtime_ready=false不得自行改成已通过运行验证。
>
> 不把本事件真实评论、转发立场、情感标签和全局相信比例加入个人资料。不将完整来源审计文件作为用户观察。现阶段先完成静态结构检查与固定回答的接口测试，不自动调用付费模型。
>
> 最后交付：平台字段映射、实际完整提示词、未解决配置项、是否支持自定义provider的检查结果、预计调用量。若平台只允许导入资料而不允许研究层代码，说明限制，不能用上传MD冒充已完成运行时适配。
