# 同一个模型在两个框架中的比较方案

状态：方案，尚未实施或运行。适用独立 TESTPROJECT。本文不依赖本地目录或原始 Excel，替代此前“必须取得原始工作簿才能比较框架”的限制。

## 1. 目标与判断标准

比较对象是：**现有 Python 工程的运行与记录方式，以及 SocioVerse2 的运行与记录方式，在承载同一个已固定模型时，能否保持行为结果一致，以及运行和维护成本有何不同。**

本次不比较哪种框架更能模拟真实人类，不比较 LLM 与概率行为的优劣，也不以产生更好的辟谣效果作为框架成功标准。

原则：先证明模型执行等价，再比较运行成本、恢复、分支和开发操作。若改变框架后科学结果明显变化，先按迁移差异排查，不能直接说新框架发现了新机制。

## 2. 推荐路线：一个模型核心，两个承载适配器

```text
同一份冻结输入 + 同一份初始状态 + 同一份模型规则 + 同一随机性合同
                              │
                   与框架无关的共享模型核心
                    ┌─────────┴─────────┐
             Python承载适配器       SocioVerse2承载适配器
                    │                    │
             调度、应用、记录       调度、应用、记录
                    └─────────┬─────────┘
                    标准化轨迹与结果比较
```

共享核心只负责本研究的领域规则，例如接触判定、状态转移、概率决策、政策作用和指标定义；适配器处理生命周期、数据转换、调度对接、记录与恢复。不能把整个旧 runner 塞进 SocioVerse2，再把外层包装称为使用新框架运行。

采用共享核心能减少“两个实现把同一公式写得不同”造成的差异。但这验证的是承载等价，不是两个独立实现互相验证模型理论正确。共享核心仍须有人工可判定的小例子检查，防止两边一致地犯错。

目前旧 Python 项目是 LLM／Mock 与信息流实现。遵守用户保留原稿概率的要求，比较中的 A 应是**在旧运行组织上接入共同概率核心后的版本**，B 是该核心的 SocioVerse2 适配版本。旧版原封不动的 LLM 曲线只作历史记录，不作为等价目标。

## 3. 哪些固定，哪些允许不同

| 部分 | 必须相同 | 可以不同 |
|---|---|---|
| 数据 | 同一事件输入文件及哈希、同一文本和证据状态 | 框架内部字段命名，经适配后语义一致 |
| 人群 | 同一批582个ID、82/500身份、同一画像分配（若使用） | 存储对象类型 |
| 初始化 | 同一离散状态、位置／网络、源与政府初始状态 | 加载接口 |
| 接触 | 同一模式、判定、顺序、重复接触规则 | 批处理优化，但不能改变可见性与因果顺序 |
| 行为 | 相同PB→RC、GT→RF、适用状态、概率精度 | 调用封装 |
| 干预 | 相同T_G、In-out、GT、RF及启用语义 | 干预事件的框架表达 |
| 随机性 | 同一事件所使用的随机值，或等价可复现分配合同 | 随机状态的持久化载体 |
| 时间 | 初始化、首次更新、同轮可见性、终止边界一致 | 调度入口 |
| 指标 | 同一TBU定义及缺失处理 | 输出格式与可视化布局 |
| 工程 | 相同输出信息量、硬件与运行条件用于性能比较 | 框架调度、序列化、日志、恢复和管理成本 |

**只固定 seed 不够。** 两边抽样调用顺序不同，就可能取到不同随机值。必须对齐取值位置和事件身份。

## 6. 实施与比较分三层

### 第一层：固定接触输入，检查行为与调度适配

构造几名用户的明确状态和接触序列，用指定随机值覆盖相信／不相信、传播／不传播、接受／拒绝纠正、无接触等分支。两框架使用同一测试输入，逐项比较动作与状态。

这层隔离接触生成的不确定性，只验证行为与适配，不宣称完整环境迁移成功。通过条件为人工预期、A输出、B输出三者一致。

### 第二层：同一环境自行生成接触，检查完整轨迹

接入共同接触模型，两边从同一初始状态开始，各自通过框架推进400 ticks。必须分别生成接触，而不是一边读取另一边的正式运行轨迹来假装独立执行。

先比较每轮的接触集合与顺序，再比较抽样、状态、传播、政府作用和指标。找到第一处分歧即定位原因，不能只比较最终人数或曲线是否相近。

不同框架的时间戳、日志编号、序列化顺序不纳入科学状态等价；应转换成同一标准格式。离散状态、接触身份、动作与计数要求完全一致。涉及浮点坐标时，在运行前确定容差；容差不能掩盖接触阈值两侧产生不同事件。

### 第三层：等价通过后比较工程表现

| 维度 | 记录什么 | 如何保持公平 |
|---|---|---|
| 时间 | 初始化、每步／全程、写盘、恢复分别耗时 | 同机器、同输入、同输出信息量；冷启动与热运行分开 |
| 内存 | 基线及峰值内存 | 统一测量方法，避免并行争抢资源 |
| 记录开销 | 轨迹／快照字节数、写入耗时 | 必需字段一致，不让一边少记日志来获得优势 |
| 恢复 | 固定中断点恢复后的状态和结果 | 与各自不中断运行一致，再检查跨框架一致 |
| 政策分支 | 前史复用正确性、分支耗时和存储 | 相同分支点与干预，前史不能重新抽样 |
| 开发操作 | 添加一个政策条件、导出轨迹、恢复运行需改哪些文件或步骤 | 记录实际操作与修改范围，不主观打“先进程度”分数 |

建议性能检查先采用至少3次测量观察波动，具体次数在执行前登记；它不是研究的正式随机重复数。运行顺序交替或随机化，报告原始测量及中位数／范围，不凭单次耗时作结论。是否扩展其他人口规模另行决定，当前先固定582人。

先做共同功能范围内的比较，再展示SocioVerse2独有管理能力。某一功能旧框架没有时，写为能力差异及所需开发工作，不能把“无法执行”算成无限耗时。

## 7. 随机过程和轨迹对齐

推荐将人口、移动、行为使用的随机流分开。行为随机值的取用绑定稳定的 tick、agent_id、contact_id、规则名和该规则抽样序号。也可以为测试预先生成随机序列，但必须确保相同语义事件对应相同位置。

同一接触下PB失败时，不执行RC；GT失败时，不执行RF。随机序号策略应避免一个条件分支少抽一次导致另一框架所有后续用户错位。该策略属于共同实现约定，需记录版本；不是原稿已提供的随机算法。

每轮比较至少覆盖：

`tick → 环境状态 → 接触 → 有效决策输入 → 随机值 → 动作 → 提交后状态 → 指标`。

共享核心与适配器都需要检查。例如，核心返回正确动作而框架应用两次、T_G偏移一轮、框架多次调用观察推进了位置，都属于迁移失败。

## 9. 如何解释比较结果

- 轨迹一致而B更慢：模型得到保留，新增耗时可能来自调度、类型转换或记录；进一步分项测量，不猜原因。
- 轨迹一致且B更方便恢复、管理分支：可以说明相应工程收益，不说科学模型更准确。
- 轨迹不同：先查输入、接触、时序、随机数和提交；等价未通过前，不将差异解释为政策效果改变。
- 只验证共同核心：证明了接口承载一致，不能宣称完成独立模型复现。
- 使用已有加工输入：结论限定于这份冻结输入；未核验原始资料的限制保留，但无需因此中止承载比较。
