# TESTPROJECT 与 HiSim、SocioVerse 系列的架构对比

日期：2026-10-13。根据用户纠正重写：本文只比较 TESTPROJECT 的实际代码与《HiSim、SocioVerse 系列架构拆解与社科评述》中描述的三个框架，不再以 ABM_INFO 总项目设计为对照。

比较依据：[框架拆解原文](../../01_research_notes/current_direction/HiSim_SocioVerse系列_架构拆解与社科评述_2026-10-13.md) §3–5、§7；[子项目代码指南](PROJECT_CODE_GUIDE.md)及本地源码。外部框架部分沿用该文档的描述，本次未重新核验其外部版本或运行外部框架。相似性是功能比较，不是代码继承或性能排名。

## 1. 先给结论

TESTPROJECT 是一个固定事件传播与纠正场景的专用模拟程序。它已经实现了人群初始化、环境与暴露、模型决策、连续状态、分支和日志。

- 与 HiSim 比：最大差别是没有“少量 LLM 用户＋大量规则用户”的混合人群，也没有文本到规则层数值状态的镜像连接。
- 与 SocioVerse 1.0 比：四类功能都有对应，但固定在一个传播研究协议中，尚未抽象为支持不同研究场景的通用模块。
- 与 SocioVerse2 比：已经具备纵向运行和共同前史干预分支；缺少更通用的运行接口及研究版本管理。不能把现有快照和分支误写成尚未实现，也不能把它们等同于完整研究平台。

其问题不是“没有架构”，而是环境、指标和研究规则的可替换范围较窄。是否扩展，取决于后续是否需要更换场景或行为实现；增加框架层数本身不会提高模拟人的准确性。

| 测量 | 固定函数计算接受率、首次拒绝等 | 文本编码与群体轨迹 | 按场景评估回答和行为 | MetricCollector 与记录报告 |
| 主要边界 | 专用规则多；目前实测为工程与 Mock | 文本测量、混合连接与成本分配假设 | 框架设计不等于所有场景均已实现 | 可追踪、可分支不等于真实行为已验证 |

表中“文档未提供”不表示该框架绝对没有相应功能。

## 3. 与 HiSim：分组相似，计算架构不同

### 3.1 两组用户究竟代表什么

原文 §3 描述 HiSim 的核心用户由 LLM 生成行动和文本，普通用户主要依据数值规则更新。

TESTPROJECT 的圈内 82 人、圈外 500 人不是这种计算分工。两组共享同一个 provider；差异主要是是否直接关注源账号、设定的初始倾向以及干预抽样资格。

```text
文档中的 HiSim：
LLM 核心用户 → 文本 → 编码为数值 → 规则普通用户
                                  ↓
                           规则用户之间互动

TESTPROJECT 的 HTTP 模式：
圈内用户 ──┐
           ├─ 可见帖子 → 同类 LLM 决策器 → 信念、评论、转发
圈外用户 ──┘                         ↓
                               后续轮次帖子池
```

因此不能把 82 人称为 LLM 核心节点、500 人称为规则节点。Mock 也不是 HiSim 式规则普通用户：它只是按哈希生成协议测试样例。

### 3.2 模块怎样对应

| HiSim 拆解中的职责 | TESTPROJECT 对应 | 关键差别 |
|---|---|---|
| Profile | observed_profile、信任和分享等设定；_make_view | 真实字段仅账户计数；心理与行为特征为设定，未使用历史文本构成完整角色 |
| Memory | agent.memory | 保存最近 5 个实际决策轮，不含独立检索和记忆归纳模块 |
| Action | provider.decide | 只有沉默、评论、转发；没有独立原创发帖或点赞动作 |
| Selection | build_feed | 明确由 Python 执行关注、推荐、帖龄和重复读取规则 |
| Message | _source_post、_official_post、_user_post | 来源帖预置；评论由模型生成，转发继承内容；没有规则层消息表示 |
| Update | 返回 belief_score 后由 step 写回 | 无独立数值意见更新内核 |
| 文本—数值连接 | 没有对应镜像层 | 模型直接返回分数与公开立场，无单独文本编码后传给规则人群的步骤 |

原文指出 HiSim 原设计未建模普通用户对核心用户的反向影响。TESTPROJECT 两组之间存在跨组关注边和推荐渠道，用户帖子可以跨组流动，但这并不表示每个人每轮都会收到另一组信息。它不受相同的规则层—LLM 层单向连接结构限制，因为根本没有这两种层。

### 3.3 对我们有什么实际含义

HTTP 模式下，TESTPROJECT 每个实际有暴露的个体—轮次都需要一次决策，重试另计。HiSim 式混合结构可减少昂贵调用，这是结构上的成本方向判断，不是本次成本实测。

如果引入规则用户，还必须回答：哪些用户分配给规则、规则怎样更新、文本怎样变成规则输入、规则用户怎样向 LLM 用户传播。仅把某些调用换成 Mock 不构成有效混合模拟。

同时，TESTPROJECT 的 belief_score 和 public_stance 分字段保存是一项有用区分，但二者由同一模型同时产生。它避免了直接用公开情感值覆盖信念的特定路径，却没有因此证明分数对应真人内在判断。

## 4. 与 SocioVerse 1.0：主要区别在可复用范围

原文 §4 的四模块，与子项目有直接的职责对应：

| SocioVerse 1.0 模块 | 子项目位置 | 当前能做什么 | 替换时的限制 |
|---|---|---|---|
| Social Environment | event、posts、follows、build_feed | 为个体形成可见信息和传播环境 | 单事件、固定网络及投送结构写入核心规则 |
| User Engine | import_data、initialize、attach_donor_profiles | 导入计数画像并分配给模拟人 | 不是通用用户检索服务；特征分布为专门设定 |
| Scenario Engine | config、cli、runner.execute、policy_spec | 指定条件、轮次、分支、参数网格 | 重点支持现有传播与纠正协议 |
| Behavior Engine | provider.decide | 将个体输入转换为判断与行动 | 六字段协议与帖子行动绑定 |

### 4.1 我们不是缺了四类功能

这些职责已经存在，只是没有全部做成独立可替换的接口。例如，把人数从 582 改成另一组合法人数主要是配置工作；但改成访谈、投票或购物选择，不能只换提示词，还要改输出协议、状态更新、校验和指标。

这说明当前程序是专用实现。它更直接地服务当前任务，但对不同任务的复用成本更高。四模块名称本身并不能证明外部框架的行为更准确。

### 4.2 画像数量与行为信息量不同

已跑的 event_052 有 305 份画像，赋给 582 个 Agent 时重复使用部分模板。实测账户字段为粉丝数、关注数、累计发博数；身份组别、活跃概率、信任、分享倾向和初始倾向主要来自实验设定。

SocioVerse 1.0 拆解强调用户池的组织与目标人群选择。借鉴重点应是资料来源、适用人群、属性误差和输入增益检验，而不是单纯增加画像数。更多账户资料是否改善行为预测，本项目目前没有对应实测证据。

## 5. 与 SocioVerse2：运行循环相近，接口和研究管理范围不同

### 5.1 四接口在子项目中的位置

| 文档中的接口 | 子项目对应 | 已实现程度 |
|---|---|---|
| PopulationProvider | initialize + attach_donor_profiles | 能产生固定身份和初始状态；仍是专用函数 |
| EnvironmentProvider | build_feed + step + posts/follows | 能组织观察和行动后果；环境与部分行为规则集中在 core.py |
| DecisionModel | provider.decide(view, call_identity) | 已有清晰替换边界，Mock 与 HTTP 实现共享调用形态 |
| MetricCollector | _round_metric、individual_tbu、summarize | 已计算逐轮与终点指标；不是通用可插拔指标收集接口 |

最接近通用接口的是 provider。但 runner 仍显式限制模式为 mock/http；要引入新决策器，除提供 decide 方法外，还要检查 CLI、模式校验和 manifest 记录。不能把函数可注入误写成所有实现已经可以无修改接入。

### 5.2 五阶段执行基本可以对应

```mermaid
flowchart LR
    A["外部更新：到时生成纠正帖"] --> B["观察：build_feed 与 _make_view"]
    B --> C["决策：provider.decide"]
    C --> D["应用：step 统一写回"]
    D --> E["记录：commit 与指标"]
```

这对应原文的外部更新、观察、决策、应用、记录。TESTPROJECT 还明确保证本轮新用户帖下一轮可见、没有信息不更新、决策全部有效才提交。

差别在于，子项目把外部更新限定为当前事件和纠正投送，观察规则与状态写回集中于一个核心模块；并没有提供任意环境更新或步内多次互动的通用接口。不能仅凭相同阶段名称推断执行顺序和边界条件完全相同。

### 5.3 我们已经有分支，但没有完整研究版本系统

现有 runner 的顺序是：

1. 为一个 event、d_seed、seed 运行无干预母轨迹至第 80 轮。
2. 读取 T_G−1 轮末快照。
3. 复制状态并写入该分支的纠正时间、对象和来源线索。
4. 运行后续轮次，保存独立输出。

这是实际实现的共同前史分支，不是计划。此前测试也确认第 50 轮分支与母轨迹前 49 轮一致。

但分支范围固定在当前干预协议。改变人口、行为规则或其他配置时，程序主要通过 manifest 校验拒绝复用不匹配目录，要求另建输出。它没有完整管理“为什么改设计、哪些假设改变、各版本验证依据和结果比较”的研究循环。

所以应区分：

- 恢复：继续未完成的同一条轨迹。
- 分支：从同一段已实现历史引入指定改变。
- 新版本：修改研究或实现设置后重新运行并追踪修改依据。

现有代码明确支持前两者的一定范围；新版本管理主要依赖研究者的外部组织。

### 5.4 日志和回放不能混为一谈

TESTPROJECT 已有逐轮压缩快照、状态哈希、决策输入与返回、HTTP 缓存和预算、状态表及曝光记录。这些足以支持本次输出核查、断点恢复和导出重建。

但它没有独立的“固定已记录行动，替换环境实现后重新执行”的通用回放入口，也没有据此完成跨框架一致性检查。SocioVerse2 拆解中的回放也有适用条件，不能因为外部文档使用 replay 就假定所有研究都可回放。

此外，相同母轨迹不等于后续模型采样完全配对：现有分支分别调用 HTTP 模型；Mock 还把分支 run_id 纳入哈希，分支名称变化本身即可改变结果。

## 6. 社科评述部分对这个子项目提出什么问题

这一节沿用原文 §7 的评价问题，不增加新理论构念。

| 原文要求区分的问题 | 子项目当前状态 | 还缺什么证据 |
|---|---|---|
| 程序正确与行为可信 | 61 项测试与两条完整 Mock 轨迹已通过 | 真实模型在独立人类数据上的表现 |
| 资料相近与反应相近 | 真实账户计数附加到设定用户 | 这些字段是否改善判断和分享预测 |
| 初始状态与更新能力 | 初始倾向进入首次暴露输入 | 暴露前后判断变化的独立检验 |
| 公开表达与内部判断 | 分字段但同一次模型生成 | 与独立测量的对应及分歧 |
| 单轮与长期 | 实现 80 轮持续状态 | 多轮误差累积及群体分布验证 |
| 干预前拟合与干预反应 | 能创建共同前史分支 | 对现实条件改变方向和幅度的验证 |

HiSim 拆解明确介绍了单轮与群体轨迹验证，不能笼统说外部工作“只有架构没有验证”。另一方面，这些外部研究的验证也不能替代当前子项目自身的行为验证。

当前纠正文本为无外部证据的实验脚本。程序记录首次拒绝能说明模型中发生了什么，不能据此判定现实事件真假或政府纠正的现实效果。

## 7. 对接手者最有用的判断

| 目标 | 从哪种架构借鉴 | 当前具体落点 | 不应直接做的事 |
|---|---|---|---|
| 降低真实模型调用成本 | HiSim 的混合计算思路 | 先设计规则决策接口及双向信息连接 | 将 Mock 当作正式规则用户 |
| 更换人群或研究场景 | SocioVerse 1.0 的四模块分工 | 分离人群加载、场景规则、环境和行为协议 | 只换提示词就宣称换了研究场景 |
| 更容易替换环境与指标 | SocioVerse2 四接口 | 保留现有运行循环，逐步抽出环境与指标接口 | 为追求模块数量重写已验证存储 |
| 管理反复修改与比较 | SocioVerse2 研究循环 | 增加版本清单、修改理由、输入版本与比较记录 | 把新的输出文件夹视为完整版本系统 |
| 提高对人的行为解释能力 | 原文的验证要求 | 同输入下与简单基准比较，独立验证判断和分享 | 把顺畅文本、通过测试或拟合一条曲线当作充分证据 |

这些是条件式工程建议，没有在本次改动中执行。若近期只运行当前协议，现有模块足以继续做工程检查；是否需要混合用户或通用场景，应由研究目的和验证需求决定。

## 8. 最终定位与代码入口

从本文档的架构维度看：TESTPROJECT 与 HiSim 的相似主要在社交传播任务；与 SocioVerse 1.0 的相似在功能分工；与 SocioVerse2 的相似在连续状态、逐轮执行与干预分支。这是结构映射，不是同源代码判断，也不是复现证明。
