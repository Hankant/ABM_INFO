# V4混合模型环境设定

更新：2026-10-18。状态：已补充工程首跑配置草案。下列具体数值供构建agent落地配置，不代表原稿已验证参数或正式实验条件；本次不启动模型调用。保留旧版本，本文件不表示环境已实现或已运行。

## 1. 共同世界

普通用户582人，305名LLM驱动、277名规则驱动；身份以 [基础信息表](./01_Agent基础信息表.csv) 为准。SOURCE和GOVERNMENT是额外角色，不计入582人。

两类用户处在同一网络、使用同一套活跃和信息展示规则。LLM／规则类型不自动带来不同的关注数、上线机会或展示优先级。

采用有向关注网络，取消旧空间的坐标、圆半径、移动速度和反射。inside表示关注原帖发布者，outside表示不关注，不表示真实地理位置。基础表的账户关注数量不是模拟网络的现成边表。

### 首跑网络配置

| 参数 | 首跑值 |
|---|---|
| 每人关注同组普通用户 | 8人 |
| 每人关注另一组普通用户 | 2人 |
| 关注原帖发布者 | 82名inside用户额外关注SOURCE；500名outside用户不关注 |
| 初始关注政府 | 无；政府通过定向投放接触用户 |
| 自关注、重复边 | 禁止 |
| 动态关注／取关 | 关闭 |
| 网络生成种子 | 20261018 |

8条同组边＋2条跨组边借用既有single_event配置作为工程起点，不声称来自原表的真实关注网络，也不把它直接定义成“信息茧房程度”。网络由5820条普通用户关注边和82条SOURCE关注边构成，共5902条有向边。

生成算法：按agent_id升序遍历；候选ID升序排列，排除自己。使用独立的PCG64随机流（种子20261018），分别对同组、跨组候选无放回抽样8人、2人。保存实际边表、随机库版本及哈希，后续复用边表，不仅凭seed声称可复现。

边follow(i,j)表示i关注j，信息候选方向是j→i。不强制互相关注。LLM和规则用户都使用同一生成方法，不按decision_mode优先连接。边表由构建agent运行时生成，属于运行产物，不增加本次四份交付文件。

## 2. 信息怎样流动

关注关系提供候选内容；实际看到什么由以下首跑规则决定。

| 参数 | 首跑值 |
|---|---|
| 活跃 | 每轮全部582人检查信息流；活跃概率1，不引入个体差异 |
| 每人每轮帖子上限 | 5条，包含定向投放占用的名额 |
| 普通帖子排序 | 发布时间从新到旧，同时间按content_id升序 |
| 重复展示 | 同一投递记录ID每人最多展示一次 |
| 每个帖子附带评论 | 最多2条，取已可见最新评论，同时间按comment_id升序 |
| 每帖有效期 | 发布步起40轮；满足0≤当前步−发布步<40时有效 |
| 推荐算法 | 关闭，无额外推荐槽位 |
| 无新帖子 | 保持状态，不调用LLM、不抽行为概率 |
| 新行动可见时间 | 下一轮 |

普通候选包括已关注账号发布或转发的有效内容。每条转发使用独立投递ID，同时保留root_content_id；同一根内容通过不同用户转发可以再次接触，但不能把同一投递记录重复当新消息。每人对同一根内容全程最多转发一次。正文与转发附言分别显示，不丢失原始出处。

评论只随本轮展示的帖子提供，不独立触发额外决策；因此首跑不包含“只因新评论而重新打开已读帖”的行为。多个帖子在一次用户决策请求中处理，不按每帖分别调用LLM。

两类用户的转发均能进入其他用户后续的信息流，支持LLM→规则和规则→LLM传播。规则用户首版不生成自由评论，也不对评论做语言推理。自由评论可以影响LLM判断，不能无说明地改变规则用户的概率。

每条帖子、评论和转发保留内容ID、发布者、时间和来源关联。程序凭内容关联识别原帖或纠正的转发，不凭LLM文本里的“辟谣”字样判定其是真实纠正。

## 3. 每轮顺序（建议）

1. 加入到时发布的原帖或政府回应。
2. 从同一环境状态为各用户生成实际观察。
3. 根据decision_mode调用LLM或概率规则。
4. 统一提交判断与行动；本轮新评论和转发下一轮才可见。
5. 保存观察、判断、行动和本人经历。

首跑时间为tick 0至40，正式决策发生在tick 1至40，每tick一轮互动。tick不换算为现实分钟。原帖在tick 0发布并登记，tick 1起可展示；tick 0不调用决策。初始信念统一记为unjudged（尚未判断），不是uncertain（接触后不确定）；个人记忆为空，不根据群体或账户属性预先抽相信。此项是V4沿用此前建议的初始化约定。

## 4. 政府回应

### 首跑排程

| 时点 | 操作 |
|---|---|
| tick 0 | SOURCE发布原帖P001；记录初始世界 |
| tick 1—19 | 按关注流传播，没有政府投放 |
| tick 20（T_G） | GOVERNMENT发布实验回应G001，在观察前完成一次定向投放 |
| tick 21—40 | 不追加定向投放；已产生的转发按普通关注流传播 |
| tick 40结束 | 保存快照和完整轨迹，停止 |

首跑目标策略为inside：在82名关注者中均匀无放回抽40人；对LLM／规则类型不设置配额。独立使用PCG64随机流、种子20261019，候选按ID升序，保存实际名单。

本次明确采用“保证展示的定向投放”：tick 20被选中的40人将G001放在信息流第一位，占用5条上限中的1条，其余最多4条仍按时间排序。全部人活跃，因此本设置下恰有40人当轮直接看到回应；这是一项实验性展示规则，不等于全员广播或自动接受。投放不新增永久关注边。

以后切换random时从582人抽40人，outside时从500人抽40人，保持其他规则不变。若候选不足40人，只覆盖全部候选，记录实际人数，不跨组补人、不重复投放。首跑只执行inside一次，不自动展开三组实验。

政府直接发送和普通用户转发回应保留不同来源标识；是否使用同一GT仍须按行为合同明确，不能由展示模块代为决定。

## 7. 首跑模型、记忆与预算

### 模型配置

下列服务信息来自现有项目single_event配置，本次只沿用已记录配置，不代表已验证网关可用或模型别名对应官方固定权重版本。

| 项目 | 首跑值 |
|---|---|
| 调用接口 | OpenAI兼容接口 |
| base_url | https://api.zetatechs.com/v1 |
| 请求模型名 | deepseek-v4-flash |
| 凭据 | 从运行环境RUMOR_LLM_API_KEY读取，不写入文件 |
| temperature | 0.7 |
| top_p | 0.8 |
| 最大输出 | 512 tokens／请求 |
| 最大输入 | 4096 tokens／请求 |
| 返回 | 单个JSON，按固定提示词字段校验 |
| 超时 | 90秒 |
| 并发 | 最多5个请求 |
| 重试 | 每次逻辑决策最多1次重试；仅超时、限流或临时服务失败；重试计入预算 |

305名LLM用户全部使用同一模型和模板。记录请求模型名、服务返回model字段和参数；若别名或参数不受支持则停止并报告，不静默换模型。环境中没有凭据时只允许离线接口测试。

个人记忆按本文件第10节管理：每次输入最近5次成功决策所对应的个人经历，并单独提供当前信念。观察记录包含实际可见文本或可解引用的内容ID，不能只给无法读取的ID。后台保存完整历史；不生成长期反思，不自动重写persona。

输入超过4096 tokens时保留固定指令、稳定资料和当前信念，先删除最旧记忆，再减少附带评论，最后从信息流尾部移除帖子；记录实际送入模型的内容。若仅固定提示词加首条完整帖子仍超限，记录输入失败，不偷偷改写正文或扩大预算。不能已在日志中声称看过被预算裁掉的内容。

### 预算和停止条件

| 项目 | 限额 |
|---|---:|
| 首跑完整模拟 | 1次，40轮 |
| 最大API请求次数 | 12200，包含重试 |
| 累计输入token上限 | 49,971,200 |
| 累计输出token上限 | 6,246,400 |
| 正式参数组合批量运行 | 关闭 |

12200=305×40，是每轮所有LLM用户都有新内容时的无重试理论决策次数；实际按有新内容的用户调用。重试共享总额度，可能使运行提前停止。每次请求前按完整输入计数并预留最大输出额度；触及任一上限时暂停并保存快照，不改用规则用户填完剩余结果，不把部分轨迹标为完成。

上述是token与请求硬预算，不是货币预算；当前没有核实该网关价格，不能填造人民币金额。执行前按服务实际报价计算上限，并在平台设置可接受的费用额度。本文件不授权自动消费或自动充值。

工程检查先用固定回答跑完整排程，再进行最多20个真实请求的接口检查；20个请求计入其所属运行预算，不能用这一检查声称已完成40轮传播。只有服务可用、行为合同齐备且费用上限已配置后，才可另行启动完整首跑。

## 8. 信息边界与输出

普通用户只获得本人可见内容和允许读取的本人经历，不得读取全体相信比例、研究者真假标签、别人的私人判断或未来回应。

记录相信、不确定、不相信、评论、转发和失败，分别报告全体及两类决策用户的结果。调用失败不是不相信；不确定也不直接计为接受纠正。原稿TBU在三态判断下的口径需另行确定。

## 10. V4新增：四部分分别保存和更新

| 部分 | 内容 | 更新责任 |
|---|---|---|
| 稳定persona | 基础表中的账户属性、有依据的事前经历；本版未知经历留空 | 初始化加载，一次运行内不重写 |
| 当前状态 | 对原始主张的current_belief及上次更新时间 | 合法决策提交后更新 |
| 个人记忆 | 本人实际观察的内容、当时判断、自己的评论或转发 | 每轮提交后追加 |
| 当前观察 | 本轮实际展示的帖子、回应、可见评论 | 环境依据网络与阅读规则生成 |

所有判断都针对P001的原始主张，不是评价“是否相信纠正这句话”。当前状态不依赖旧记忆是否仍在窗口内：删除较早记忆不能把current_belief重置。LLM可在新内容下从相信转为不确定或不相信，也可反向改变；其变化本身不是正确性证据。

稳定资料中的事前来源评价只表示初始背景，不永久规定后续判断。当前原表没有相关信息，留空，不抽取政府信任百分比，不把unknown解释为低信任。V4暂不增加独立的动态来源信任更新模型。

公共评论库与个人记忆分开。公共库保留已发布评论，但仅在用户实际看见时才进入其个人经历。同轮新评论下一轮可见，每帖仍最多展示2条；未展示的评论不能通过记忆检索进入输入。评论本身不等于发布者的私人信念。

一次个人经历至少记录agent_id、tick、实际展示内容ID及对应文本、belief_before、belief_after、已提交评论和转发。失败请求保留观察与错误日志，标记decision_status=error；不生成成功经历、不伪造判断，不将其当作uncertain。本人最新5次成功经历用于下次决策；首次写“暂无”。当前轮观察只放当前观察段，不提前重复写入历史。

禁止输入邻居私人相信比例、邻居政府信任均值、全平台信念分布、未来回应和研究者真假标签。V4也不额外计算评论支持比例，直接提供实际可见评论。规则用户通过其公开转发影响LLM观察，而非通过内部状态直接影响LLM。

277名规则用户保存同样可追溯的状态与接触日志，但不用自然语言persona或LLM记忆推理。其GT抽样失败应保持原状态，不能把unjudged自动改成uncertain；其他规则按单独冻结的概率合同执行。

后台日志、个人记忆和公共库均是运行产物，不增加本次四份交付文件。记录为dry_run的固定回答只能用于工程测试，不能与真实模型输出混合用于研究结果。
