# 单事件模型：从谣言传播到政府纠正

本版只选辽宁扶贫视频事件（event_052），保留582名模拟用户，默认第20轮加入政府纠正，连续运行到第80轮。目的是先看懂一个事件怎样传播、用户怎样相互影响、纠正怎样继续传播。**不自动运行75个事件，也不自动展开全部参数组合。**

## 先打开哪一个文件

1. 双击 `查看已完成的演示.cmd`：直接看已经跑完的离线流程演示，可拖动轮次、切换用户、查看他读到的信息和发言。标有Mock的曲线只说明程序能运行，不代表真实LLM的判断。
2. 看 `deliverables/single_event/模型流程图.png`：左边是主体和网络，右边是每轮处理过程。
3. 想自己再跑一遍，双击 `单事件离线演示.cmd`。程序不联网，约需几分钟，自动生成并打开新的报告。
4. 要运行真实模型，双击 `单事件真实运行.cmd`，输入本次累计请求上限和API Key（隐藏输入）。不设置预算就不会发出请求。真实运行仍为582人；达到上限会停止，绝不自动改用Mock补完。

本机优先使用Codex自带Python；换电脑需Python 3.11或以上。核心运行、报告和测试不依赖第三方Python包。重新从原始Excel导入需安装 `requirements.txt`；所附单事件数据已经准备好，无须再次导入全部文件。

## 真实数据究竟用在什么地方

| 数据 | 本版用途 | 不据此推断的内容 |
|---|---|---|
| Sheet 1源帖 | 第0轮发布的待核实主张与源文本 | 不把该主张预先标为真实或虚假给Agent |
| 用户粉丝、关注、发帖数 | 每名Agent的公开账号画像 | 不把“关注数量”当作关注谣言博主的证据 |
| 250条评论、72条有效转发 | 逐个用户提取发言次数、转发占比、评论长度、问句比例；作为LLM行动与表达的统计参考 | 不把评论中的历史立场设为用户初始信念，不推断真实政府信任 |
| 305份去重用户画像 | 先无放回抽取，再有放回补足582人；各模拟身份分别维护信念和记忆 | 重复画像不等于同一模拟用户 |

这里的“学习”是**从数据提取行为特征并放入提示词**，没有微调大模型，也没有估计经过实证验证的行为系数。行为统计覆盖本事件观察期，属于回顾性情境设定，不是事件发生前的心理测量。转发占比是“记录下来的公开发言中，有多少属于转发”，不是“每次浏览后转发的概率”。多数用户记录很少，LLM只把它当有限参考。

原始历史评论可能已经提及纠正。因此，本版不把整批历史评论提前塞进Agent记忆，也不把历史发言当作新生成的行为。去标识后的47条样例保存在 `data/single_event/event_052/local_comment_examples.json`，用于本地核对提取依据；它们不发送给API。运行中的评论与转发由模拟用户逐轮产生，再被其他用户看到。

## 用户怎样互相影响

每人关注8名同圈用户、2名跨圈用户；82名圈内用户另外关注谣言源。边有方向：A关注B，就可以在关注流中看到B的发言。B也可能通过自己的关注关系、推荐、话题讨论或回复读到A的发言，因此网络可以形成往返影响。**不要求任意两人都互相关注。**原始数据没有完整关注边和回复父节点，这张网络属于实验设定。

每轮按以下顺序进行：

1. **冻结轮初信息。** 所有人基于同一轮初可见帖子决策，不能提前看到别人本轮刚写的内容。
2. **打开信息流。** 活跃用户最多读取1条关注流内容；以0.1概率额外读取1条推荐内容。自己帖收到的回复也能打开讨论入口。
3. **读取相关讨论。** 在当前读到的来源话题及自己的回复中，额外读取至多2条评论、1条转发。优先顺序是：自己帖的回复 → 已关注用户 → 其余可见讨论；同层内偏向较新的帖子。回复占用这3个槽位，并不是无限追加。源帖及其派生帖属于一个来源话题，政府纠正及其派生帖属于另一个来源话题。
4. **LLM形成判断。** 输入包括本轮帖子、引用的原文、来源线索、已关注/同圈/跨圈关系、真实行为统计、先前信念和最近5次决策记忆。只汇总亲眼看到的明确评论立场，不能读取全网私下信念。无附言转发不等于明确背书，也不泄露转发者未写出来的态度。
5. **选择行动。** 输出相信原主张的0–100分，以及沉默、评论或转发。评论和转发只能针对本轮看到的帖子。没有曝光则不调用LLM，分数保持不变。
6. **统一提交。** 本轮所有决策有效后才提交。新帖子下一轮可见，继续沿圈内和跨圈关系传播。失败则保留上一个完整轮次，已成功的API响应由缓存复用。

## 政府纠正怎样加入

默认第20轮向圈内40名用户各直接投送一次；这40人即使当轮不活跃也会读到。之后没有持续、全员的政府强制投送，主要依靠用户对纠正的评论和转发继续扩散。原谣言和纠正相关讨论可以同时存在，用户可以相信、怀疑、拒绝，也可以之后再次改变看法，程序没有写死“政府一定成功”。

你此前说明没有对应官方纠正和证据文件，所以本版仍采用已约定的实验澄清文本，不冒充采集到的真实官方事实。GT通过发布账号的历史核验记录线索呈现；GT=0.6对应“最近10条可核验信息中6条与事实一致”，它也是实验操纵。

## 编程入口与运行命令

| 文件 | 职责 |
|---|---|
| `empirical.py` | 从原始导入档案提取无正文的行为统计，并校验字段 |
| `runner.py` | 画像分配、单事件连续轨迹、缓存恢复、结果导出 |
| `core.py` | 网络、曝光、评论区、同步更新、帖子传播、TBU |
| `provider.py` | LLM提示词、JSON校验、请求预算、重试及缓存；Mock严格分离 |
| `report.py` | 从已提交的记录生成可逐轮浏览的本地展示 |
| `tests/` | 同轮隔离、圈内跨圈曝光、回复优先、无立场泄漏、预算与续跑等验证 |

以下命令在解压后的项目目录执行：

```powershell
# 完整离线测试
python test_all.py

# 一个事件的一条离线轨迹；自动生成HTML报告
python run.py single-event --event data/single_event/event_052/event.json --provider mock --tg 20 --output outputs/my_single_demo

# 真实运行：先由你确定累计请求上限，安全输入Key；程序不会默认增加预算
.\start_single_event.ps1 -Mode http -TG 20 -Output outputs/my_single_http

# 若达到预算，续跑使用同一目录和原参数；在提示中填写你新的累计上限
.\start_single_event.ps1 -Mode http -TG 20 -Output outputs/my_single_http

# 单独重新生成报告（替换为实际run目录）
python run.py report --run outputs/my_single_demo/runs/event_052_d0.2_s1_timeline_t20_inside_gt0.6
```

最后两个真实运行命令会先询问上限，没有自动默许10000次或其他次数。Key不保存进配置、压缩包或报告。旧的 `run` 命令仍表示“无纠正父轨迹＋政策分支”；本次应使用 `single-event`，它只跑一条含干预的轨迹。

## 怎样判断模型是否按设计运行

先在页面选择第1轮，确认源帖先出现；切到第19轮，用户已经通过关注、评论和转发形成不同判断；第20轮出现40次政府直接曝光；之后查看纠正信息是否通过用户继续扩散。选中一个用户，可以逐轮核对他读到的帖子、引用原文、来源可信度线索、分数变化、行动和传播链。页面会保留未完成的标记，不能把预算耗尽后的部分轨迹看成80轮结果。

程序测试和离线Mock不能证明真实用户会怎样反应，也不能证明政府干预有效。获得真实LLM过程之后，仍需重复种子和无干预对照，才能进一步比较效果；本次先把单事件过程做清楚。
