# V3：SocioVerse2 结构调整与最小验证

修订日期：2026-10-18。状态：设计草案，未修改平台代码、未运行实验。

## 1. 最大的变化：谁来决定这个用户相信什么、做什么

旧概率版本的做法是：程序找到有效接触，然后按照 PB、RC、GT、RF 等参数抽样，决定用户相信、转发或接受纠正。

V3 的做法是：程序先确定用户实际看到了什么，再把这个用户的个人资料、当前内容和允许读取的个人经历交给 LLM，由它分别回答是否相信、是否评论、是否转发。

因此，目标人群不能只有“用户ID＋属于哪一组＋概率参数”。需要给每个人准备一份有来源的个人资料，并在模拟过程中保存他自己的经历。平台仍然负责网络、展示、时间和保存结果，LLM不自行决定这些规则。

这里需要区分两种 agent：

- 构建 agent：帮助研究者在 SocioVerse2 中准备和实现研究的工具。
- 模拟用户 agent：研究中的每一名模拟微博用户。

下面的个人资料和经历都属于“模拟用户”，不是给构建工具设计人格。

## 2. 目标人群应该拆成三份资料

### 第一份：用户身份表——这个人是谁、在网络哪里

| 字段 | 示例 | 如何使用 |
|---|---|---|
| 用户ID | U001 | 全程不变；所有版本都用这个ID对齐 |
| 是否关注原帖发布者 | 是 | 决定相关网络关系；不直接决定相信 |
| 关注哪些其他用户 | U014、U025 | 交给环境决定可能看到的内容 |
| 资料来源 | 原数据、研究者设定或缺失 | 便于检查哪些是数据、哪些是假设 |

若继续采用82名关注者和500名非关注者，则沿用现有582个ID，不为四个验证条件各造一批新用户。最终人数仍由研究者确定，本次不重新抽样。

### 第二份：个人资料表——模拟开始前，这个人有什么相关经历和习惯

建议先保留与本研究直接相关的内容：

| 字段 | 可以填写什么 | 不能怎么填写 |
|---|---|---|
| 平时关注的内容 | 社会新闻、当地事务等，有资料才填 | 凭年龄猜测兴趣 |
| 对原帖发布者的既往经历 | 曾看过哪些内容、是否发现过错误 | 关注者一律写成“容易相信” |
| 对官方账号的既往经历 | 已知的接触或评价；无数据则标为实验设定 | 直接写“必须接受政府纠正” |
| 过去如何分享信息 | 可观察的分享习惯，或明确标注的实验设定 | 把本次是否转发提前写死 |
| 年龄等背景 | 确有来源且研究需要的资料 | 为了让人看起来不同而任意拼造 |

每项内容同时保存来源。没有真实资料时，可以设计假设用户用于模型探索，但必须注明“假设”，不能伪装成从真实账户提取的画像。

以下只是说明怎样写，**不是已采集数据，也不是正式人群分布**：

| 用户 | 对同一发布者的经历 | 分享习惯 |
|---|---|---|
| U001 | 关注过一段时间，过去看到的几条消息后来得到证实 | 偶尔转发自己认为重要的消息 |
| U002 | 同样关注该账号，但曾看到其更正一条错误消息 | 过去更常先评论提问，再决定是否转发 |
| U003 | 不关注该账号，之前没有接触经历 | 有时转发消息并附上自己的疑问 |

三个人不需要预设本次谁更相信。提供不同的已知经历，让其面对当前内容作判断。这些差异是否真的影响行为，是要检验的结果。

正式建群前必须确定这些经历组合如何分配、各有多少人；不能让构建 agent 自由生成582段故事后当作真实人群。先交付少量示例和分配表草案，供研究者核对，再批量物化。

### 第三份：运行经历表——这个人在模拟中实际经历了什么

这份表在开始时为空，除非研究明确提供了模拟前的历史。运行中由程序逐步填写，不由LLM凭空编故事。

| 用户 | 时点 | 实际看到的内容 | 当时判断 | 实际行动 |
|---|---|---|---|---|
| U001 | 第1轮 | 原帖P001 | 不确定 | 未评论、未转发 |
| U001 | 第2轮 | P001下的一条质疑评论C003 | 仍不确定 | 评论“有原始来源吗？” |

到了第3轮，若允许使用记忆，程序就把上述属于U001的经历提供给它。其他用户没有看到的内容、其他人的私有判断、未来纠正不能写入。

**这就是上一版所谓的“历史信息包”：这个人以前实际看到什么、当时怎么判断、做过什么。以后不再使用这个含混名称。**

个人资料中的“过去关注过某账号”是模拟开始前的设定；运行经历中的“第2轮看到C003”是模拟过程中产生的记录。两者分开保存。

## 3. 每次调用LLM，具体给它看什么

完整V3建议按下面四段拼成一次输入。第一段是所有人共用的任务说明，第二段因人不同，第三段由环境产生，第四段仅在允许使用记忆时加入。

```text
【共同任务说明】
你正在模拟一名社交平台用户。根据提供的个人资料和你实际看到的内容，
判断这条消息目前是否可信，并分别决定是否评论、是否转发。
可以相信、不确定或不相信；相信不要求转发，不相信也可以转发并质疑。
不要补充材料中没有提供的帖子或个人经历。

【这个人的个人资料】
用户ID：U001。
你过去关注过发布者A，曾看到其几条消息后来得到证实。
你偶尔转发自己认为重要的消息，但不是每次都会分享。
（这段仅为假设示例，不代表已有实证资料。）

【这一轮实际看到的内容】
当前轮次、帖子全文、发布者，以及本轮确实展示的评论。
（由程序填入，不让模型自行补全。）

【这个人此前在模拟中的经历】
第1轮看到P001，判断不确定，没有行动。
第2轮看到评论C003，仍不确定，发出询问来源的评论。
（由程序读取记录；关闭记忆时删除整段。）
```

模型输出至少包括：相信／不确定／不相信、是否评论及评论全文、是否转发及转发对象、可选转发附言。判断与行动分别保存，不能只保留一段无法统计的自由回答。

若没有新内容，首版建议不调用LLM并保持状态。这是待确认的执行建议，不代表每个时间步所有人都必须回答一次。

## 4. 四个验证条件究竟是什么意思

四个条件是**同一批模拟用户跑四次不同设置的实验**，不是把人群切成四组、每组只用一种模型。

| 实验 | 用什么决定行为 | 每个人的个人资料 | 是否告诉它此前的模拟经历 |
|---|---|---|---|
| A：概率规则对照 | 原来的概率抽样 | 不交给LLM，因为此组不用LLM决策 | 程序保留规则必需的状态 |
| B：不提供个人差异 | LLM | 不提供每人不同的经历和习惯；只用共同任务说明 | 不提供 |
| C：提供个人差异 | 同一个LLM | 每人有自己的个人资料 | 不提供 |
| D：个人差异＋记忆 | 同一个LLM | 与C中同一个人的资料完全一致 | 提供这个人此前的模拟经历 |

**我把上一版含混的“同一共同角色模板”改成了更明确的B组：不提供个人差异。** 所有人收到相同的任务说明，不意味着假定所有人都是35岁，也不意味着给所有人编造相同的生活经历。它只是一组用于比较的简化设置，不是计划中的正式V3人群。

共同任务说明在B/C/D都相同。C比B多一段“这个人的个人资料”；D比C多一段“此前的模拟经历”。这样才能知道多提供这些信息改变了什么。

用户ID、网络位置和这一轮确实看到的来源关系仍然保留，不能为了让B“相同”就把真实展示信息删掉。B也可能因观察不同而回答不同；它只是没有额外的个人资料差异。

对同一个U001、同一轮内容，直接理解为：

```text
B = 共同任务说明 + 这一轮看到的内容
C = 共同任务说明 + U001个人资料 + 这一轮看到的内容
D = 共同任务说明 + U001个人资料 + 这一轮看到的内容 + U001此前的模拟经历
```

C与B比较：提供个人资料是否改变了判断、评论和转发？

D与C比较：让用户知道自己以前看过什么、怎么做过，是否改变了后续行为？

D更接近你希望采用的正式V3。B/C是为了检查设计有没有起作用，不是建议正式模型故意让用户没有个人经历。

这里的“无记忆”只指模型输入：后台仍然保存每一轮记录。B/C不能通过同一聊天会话、上一轮回答或隐藏摘要获得历史。它们的连续记录表示逐次判断序列，不应解释为已经验证了持续一致的个人心理过程。

A与LLM不是完全相同行为空间：A不能生成评论，也未必有“不确定”状态。所以A主要作为相信和转发的规则基准，不把所有差异归为角色提示词效果。A放到新网络中后也不再是完整旧空间模型的复现。

## 5. 在SocioVerse2中，按什么顺序改

### 第一步：保留旧版本，单独准备V3

保留旧空间概率配置和结果。V3记录为新的模型设定，不能覆盖旧基准后继续称“同一个模型的框架比较”。

### 第二步：重做“目标人群”的输出

要求构建agent先交付：

1. 固定用户身份表：ID、是否关注原帖作者、来源。
2. 个人资料字段表：每个字段的含义、来源、缺失处理。
3. 几名用户的个人资料示例，以及这些资料怎样转成提示词。
4. 正式人群资料的分配规则草案：采用哪些组合、数量依据是什么、哪些是假设。
5. 同一个人的C/D资料对照，确保没有重新生成。

用户资料不足时，列明缺失；不得按圈内外自动补“高／低相信概率”，也不要求为每个人写一篇长传记。

### 第三步：改“推演”的输入组装

构建agent增加一个选择A/B/C/D的研究配置。它决定使用概率还是LLM、是否加入个人资料、是否加入模拟经历。

同时提供U001在B/C/D中的三份完整调用示例。研究者应当能直接读出三份输入的区别，不需要通过代码猜测。这是本次重构的核心验收材料。

### 第四步：加“个人经历”的保存与读取

每次决策后保存该用户的实际观察、判断和行动。只有D会在下次调用时读取。开始先采用简单、明确的按时间保留方式；保留多少条由配置确定，不先加入复杂的LLM反思和自动人格修改。

初始个人资料不被新生成的摘要覆盖。个人经历保留原始记录，摘要如果存在须能追溯；记忆读取规则在所有D运行中相同。

### 第五步：准备两种环境运行方式

第一种用于比较决策：给各实验提供事先准备好的相同内容序列，用户的回答暂不改变后续展示。

第二种用于完整传播：评论和转发会改变下一轮可见内容。

先完成第一种，确认个人资料和记忆真的按设计进入提示词，再运行第二种。

官方架构提供人群、环境、决策与指标四类研究接口；上述职责分别放在人群准备、环境观察、决策输入组装和结果记录中。这里不是要求修改平台核心引擎，也不宣称在线界面已经有A/B/C/D按钮。构建agent应检查部署版本是否支持自定义研究实现。[官方架构说明](https://socioverse.fudan-disc.com/docs/concepts/architecture/)

## 6. 最小验证怎么实际做

### 先做一段固定内容的试验

准备一段短内容序列，例如原帖、质疑评论、纠正回应。这个顺序只是说明方式，具体材料及轮次另行确定。每条内容有固定文本、ID和显示时间。

同一个U001在B/C/D看到完全相同的外部材料，但D还会知道自己的前次判断和行动。每次实验从初态开始，不让D继承C跑出来的经历；D保存的是它自己这次运行的经历。

测试中的评论来自事先准备的材料。U001新写的评论只保存，暂不发给其他人。这样能先看清“个人资料”和“记忆”的作用，不混入传播后造成的内容差异。

检查三个问题：

- C相对B，是否出现与个人资料有关的行为差异，还是只换了说话风格？
- D相对C，是否能延续并在新证据下调整之前的判断？
- 相同条件重复运行、或同义改写任务说明，结果是否过于不稳定？

人数、轮数、模型和重复次数尚未确定。先准备试验材料及调用次数估算，不自动展开大规模运行。没有真人行为作参照，以上只能证明内部功能与行为差异，不能证明模拟更接近真人。

### 再做能传播的完整试验

允许上一轮产生的评论和转发进入下一轮信息流。保持初始人群、网络、原帖、政府策略和展示规则一致。

从这一步开始，各实验实际看到的内容会因自身行为不同而分化。这属于完整模型的结果，不再要求每一轮内容完全一样。

B/C/D都有生成评论的能力，适合比较个人资料和记忆。若要把A与LLM的转发行为作更严格比较，可另做所有条件均不传播评论的试验；不能忽略A没有评论能力这一差别。

## 7. 给构建agent的直接任务

下面这段可以直接作为任务说明：

> 保留旧空间概率版本，准备独立V3草案，暂不调用真实模型。
>
> 先重构目标人群：沿用经确认的固定用户ID，将身份、个人资料、模拟经历分别保存。身份包含关注关系；个人资料只写有来源或明确标注为假设的经历与习惯；模拟经历由运行记录生成，不能预编。不要根据关注者身份自动设定更容易相信。
>
> 为同一个示例用户准备B/C/D三份完整提示词。B只有共同任务说明和当前观察；C再加入个人资料；D再加入本人此前模拟经历。三份提示词的共同部分必须一致。C/D使用完全相同的个人资料。A保留概率规则作单独对照，不借用LLM生成评论。
>
> 首先支持固定内容序列测试，暂不让新评论和转发改变后续展示。所有实验从初态独立运行，D只使用自己本次运行的经历。然后再准备允许用户行动影响下一轮信息流的完整模式。
>
> 交付身份表、个人资料字段及来源表、用户示例、资料分配规则草案、三份完整提示词、逐轮经历记录示例、四种设置的差异表、缺项与预计调用量。完成这些材料不等于已经实现或验证模型。

## 8. 验收时只需先看这些东西

| 检查什么 | 合格标准 |
|---|---|
| 同一个用户有没有被偷偷换掉 | ID、网络与C/D个人资料保持一致 |
| B/C/D究竟差在哪里 | 直接打开完整提示词就能看出新增哪一段 |
| 经历是否真实发生于模拟中 | 每条经历都能找到对应观察和行动记录 |
| 不允许记忆时是否真的没有 | 调用中无旧对话、旧回答和隐藏摘要 |
| 模型是否提前知道答案 | 不向它显示真假标签、全局相信比例与未来回应 |
| 判断与行动是否分开 | 能记录“相信但不转发”和“不相信却转发质疑” |
| 固定内容试验是否可比 | 同人同轮的外部展示内容与顺序一致 |
| 错误是否被掩盖 | 失败单列，不把调用失败记成不相信 |

判断结果中的“不确定”单列。TBU等原稿指标需要另行明确怎样处理不确定及反复改变；本次不擅自更改原有指标定义。统计上也不能把同一次运行中的每一轮、每一个用户都视为互相独立的重复实验。
