# 双框架第一阶段运行阻塞解决方案

状态：具体实施建议，新增规则待研究者确认；尚未编写或注册provider，未执行模拟。本文件不改变此前已确认的空间配置。路径均按交接文件所在位置使用相对引用。

## 1. 解决原则

不要继续把所有问题列成空值，也不要将科学选择藏进代码。下面给出一套完整的第一阶段行为约定，使实现工作有明确目标。其用途是同模型双框架的工程等价检查，不声称恢复原稿全部细节。

已确认空间基准保持：世界[-50,50]²，圆心(0,0)，固定半径20，82圈内／500圈外用户，用户步长2，政府步长1，均匀随机方向、区域边界镜面反射、移动结束后距离≤2产生接触。源固定在中心。圈层动态第一阶段不启用。

## 2. 建议采用的初始化

| 对象 | tick 0状态 |
|---|---|
| 普通用户582人 | 全部S；没有初始E/I/R；未接受纠正，不传播纠正；T_i为空 |
| SOURCE | 特殊持续谣言发送者，位置(0,0)，不计入582人，也不强行赋I状态 |
| GOVERNMENT | 特殊纠正发送者，按In-out生成并保存位置；T_G前禁用 |
| 圈层 | tick 0已经存在，半径20且固定 |
| 初始记录 | 完成身份、坐标和状态初始化后保存step 0；不在tick 0移动或接触 |

两个框架加载同一份完整初始快照。不要各自从seed重新生成坐标作为“起点一致”的唯一证明。全S是本次建议采用的实施约定，原稿叙述支持这一选择，但没有找到完整原始赋值代码。

## 3. 每个tick的固定顺序

更新tick为1至400，终点为第400次提交之后。

1. 读取上一tick末的状态与传播资格，冻结为本轮决策基准。
2. 若t≥T_G，启用政府；第一次启用发生在T_G本轮移动前。
3. 移动全部用户；已启用政府也移动。方向均由固定随机键生成。
4. 用移动后的坐标、上轮末冻结的传播资格，生成全部有向接触；政府从本轮启用即具备发送资格。
5. 按第4节为每个接收者筛选一个本轮可处理的接触，执行条件概率判断。
6. 收齐全部动作并验证后统一提交，失败时整轮不提交。
7. 记录状态、接触、抽样和转换时点。本轮新增传播资格从下一tick才作用于其他用户。

政府启用不是全员曝光。源持续发送；普通用户只有I状态能发送谣言；接受纠正且RF成功的用户可以发送纠正。观察接口本身不得触发移动、抽样或提交。

## 4. 多接触与状态规则：采用最小可检查版本

### 4.1 先筛选适用候选，再决定优先级

- 谣言候选仅对S用户适用；发送者是SOURCE或上一tick末为I的普通用户。
- 纠正候选对尚未接受过纠正的用户适用；发送者是已启用政府或上一tick末具备纠正传播资格的普通用户。
- 对每个接收者每tick最多处理一个适用接触：政府直接纠正优先，其次同伴纠正，最后谣言。
- 同一优先级有多个候选时，按带种子的稳定随机排名选一个；不按ID大小永远优先同一用户。
- 保留所有候选接触记录，注明选中或未选中原因。接触数与实际行为判断次数分开统计。
- 被选中的纠正如果被拒绝，本tick不再追加谣言判断。

这项限制减少多接触造成的重复试验，但引入了“纠正优先”和“每tick一次机会”的假设。必须写入改动表；不是原稿已明确的规则。未筛选适用状态的接触不能占用本轮决策机会。

### 4.2 谣言

对选中的S用户接触，按表中PB抽样：失败进入R；成功再按RC抽样，失败进入E、成功进入I。PB失败不抽RC。无适用接触则保持状态。

本阶段R不再变回S/E/I；E不因再次接触自动升级I。已相信者仅通过接受纠正转为R。这样的单向过程是共同简化，不能以旧LLM版本允许反复改变分数为理由替换。

### 4.3 纠正

为区分拒绝谣言与接受纠正，另存：

```text
correction_accepted: bool
correction_spreader: bool
first_belief_rejection_tick: int | null
```

建议本阶段政府和同伴纠正都使用当前政策GT进行接受抽样，另存source_role。该选择表示“纠正活动统一接受率”的简化，不表示同伴具有与政府相同的经验可信度；属于新增规则，须明确确认。以后若区分来源接受率，两框架同时升级模型版本。

GT失败：保持状态，可在后续tick接触时再次判断。GT成功：状态置R、correction_accepted=true，再以RF=.6判断correction_spreader。RF只在首次接受时抽一次，失败者不因重复听到纠正无限重抽RF。

尚未相信过的S或因PB失败而为R的用户也可以接受纠正和传播纠正，但不因此计入“相信→不相信”完成者。已接受纠正者不再执行纠正抽样。

## 5. LC与概率精度

**LC=250作为原稿的背景校准记录，不执行到期删除或状态失效。** 原稿用首末评论跨度定义LC，没有给出可核实的硬失效算法。所有持续资格按上述状态规则保持，模拟在400ticks结束。不要仅因存在LC字段而虚构计时器。

建议直接采用原稿表格值，不再运行时按比例重算：

| PBd | PB_inside | PB_outside | RC_inside | RC_outside |
|---|---:|---:|---:|---:|
| 0 | .579 | .579 | .100 | .100 |
| .2 | .679 | .479 | .117 | .083 |
| .4 | .779 | .379 | .135 | .065 |

所有抽样使用u∈[0,1)，成功条件u<p。p=0必失败、p=1必成功。表格精度选择对状态判断、参数记录和两个适配器一致生效。

## 6. 随机数合同

建议使用SHA-256的按键确定性伪随机值，避免框架调用顺序改变后续抽样。

键为固定顺序JSON数组：

```text
["rumor-spatial-v1", seed, event_id, tick,
 actor_id, channel, counterpart_id, attempt_index]
```

UTF-8编码；JSON无额外空白，字符串字段规范一致、数值键仅用整数。取SHA-256前8字节为大端无符号整数，右移11位获得53位整数n，令u=n/2^53。用于可复现模拟，不宣称真随机。

channel分别采用：init_user_position、init_government_position、move_user、move_government、contact_rank、rumor_belief、rumor_forward、correction_accept、correction_forward。每个坐标分量或抽样用途使用不同attempt_index。拒绝采样重试也增加该索引，不消耗其他用户的随机流。

actor_id、counterpart_id及候选接触标识必须跨框架一致。运行名称、框架名称、GT值不进入随机键。同一政策比较可复用随机值，但不同世界状态导致候选接触不同是合法的模型后果。相同随机键不能被重复用于本应独立的两次抽样。

第一阶段建议seed=1，仅作工程检查。正式随机重复数量不影响实现provider，可在等价通过后另行设计。

## 7. 第一次可比较运行与指标

建议基准：PBd=.2、T_G=20、In-out=2、GT=.6、RF=.6、400ticks、seed=1，各框架一次。分支只将GT改为1，分支在tick19结束状态建立，用户和政府初态及运动随机键保持一致。

这不是足以得出科学结论的重复设计，也不自动展开405组条件。

T_i建议定义为首次从E/I提交为R的tick。由于本版不允许重新相信，每人最多一次这类转换。原稿TBU只取T_i>T_G的完成者；T_i=T_G仍记录但不进入该均值；无完成者记缺失并报人数。

报告各状态人数、相信→不相信转换人数、原稿TBU及个体轨迹。新增转变比例暂缓，不定义分母，不增加统一观察窗口或共同风险集。

## 8. 接下来需要实现什么

下面是职责合同，具体方法签名和注册方式由执行agent核对其安装的SocioVerse2版本，不能凭本文假定上游API已存在。

| 模块／入口 | 实现职责 |
|---|---|
| 共享模型核心 | 上述几何、接触、筛选、状态转换和随机值函数；不依赖框架 |
| reset(seed) | 加载同一完整初始快照，校验参数及哈希；只在共同准备步骤生成一次快照 |
| advance_to(t) | 保证推进连续且每tick恰好一次；启用政府、移动、冻结决策候选；重复推进同一tick不重复移动 |
| observe_batch | 只读本轮准备好的候选、选择结果和必要状态，不改变随机过程或状态 |
| DecisionModel | 对适用的选中接触执行PB→RC或GT→RF，返回明确的动作记录 |
| apply(actions) | 验证tick、接触、接收者、概率分支、动作唯一性，原子提交；重复提交不重复生效 |
| agent_state | 返回所需当前位置、状态和追踪标识；不得擅自增加对所有用户状态的可见性 |
| snapshot／restore | 保存并恢复tick、位置、状态、资格、政府启用、未提交阶段、配置／输入摘要；先支持tick边界快照 |
| provider注册 | 实际导入实现并注册为environment.json中同一个名称rumor.environment；调用加载器验证，不仅做字符串检查 |

动作合同至少包含tick、agent_id、contact_id、before、after、correction_accepted、correction_spreader、T_i变更、抽样审计。无适用接触返回明确no-op或框架允许的空动作，不能伪造决策。

初始化数据生成、语义函数与两个适配器的职责分开。不能在SocioVerse2里嵌套运行旧主循环，否则只是在包装旧模拟器。

## 9. 解除阻塞的验收顺序

1. 用2—5名固定坐标用户验证接触阈值、PB／RC／GT／RF极值、纠正优先和同步传播延迟，结果与手算一致。
2. 通过实际框架加载器解析rumor.environment，完成reset→advance→observe→decide→apply，不依赖LLM服务。
3. 582人完整单次运行，逐tick核对坐标、候选／选中接触、随机值、动作与状态；不能仅比较最终曲线。
4. tick19快照恢复与连续运行一致；GT分支前史一致；重复调用观察和恢复不改变抽样。
5. 只有上述通过才写runtime_ready=true及equivalence_verified=true；两个字段分开记录。

schema校验通过、provider成功加载、单框架能运行、双框架等价通过是四个不同状态。

## 10. 本建议需要明确接受的研究补充

新增项集中为：全S初态；每人每tick一次适用接触且纠正优先；R不逆转；同伴纠正沿用GT；RF首次接受时只抽一次；LC仅记录不执行硬失效；按表格精度；上述随机键和测试条件。

这些约定使第一阶段模型可具体实现，但会影响传播轨迹，不能仅当作无关紧要的程序细节。本次只是把建议完整列出，没有将其标为研究者已经确认，也没有实际执行代码或替对方完成provider注册。
