# 样例工程库使用说明

版本：0.1.1；更新：2026-09-15。此版将 HiSim PDF 更新为 Git 跟踪文件。

## 1. 从哪里开始

打开 [样例索引](README.md)，选择一个样例档案。目前 HiSim 为 EX001；AnyLogic 与 LLM 技术路线暂归 EX002 候选集合。

建议阅读顺序：样例档案 → 原文和方法笔记 → 工程设计/知识图谱 → 参考代码 → 复现记录。档案里的状态说明用于判断哪些内容已经核验、哪些仍需补充。

本地可以用 Markdown 编辑器打开本库；GitHub 可直接浏览 Markdown。标注“本地 PDF”的链接只在电脑上有对应文件时有效；在线阅读请使用档案中的出版页面。HTML 知识图谱可通过项目首页列出的 GitHub Pages 地址访问。

## 2. 添加一篇新样例

1. 在索引中确认未重复收录；同一研究的论文、代码和图谱放在同一个样例档案下。
2. 分配未使用的编号，例如 `EX003_作者或项目_年份`。编号只是管理标识，不代表质量排名。
3. 建立该目录，把 `templates/EXAMPLE_TEMPLATE.md` 复制为其中的 `README.md`，填写题名、作者、年份、来源和获取状态。
4. 原文存入 `02_literature/user_supplied_originals`，在档案中链接并记录实际哈希；已有文件直接复用。可以用 PowerShell `Get-FileHash -Algorithm SHA256 -LiteralPath '文件完整路径'` 核对是否重复。
5. 登记源码上游、许可证和 commit/tag；还没下载时写“未获取”。第三方源码放在 `04_code/third_party_reference`，不要混入本项目原创实现。
6. 在本库索引增加一行，并更新档案日期和版本记录。

## 3. 怎样写工程设计拆解

先回答“模型中有什么、每一步做什么”，再映射到我们自己的架构。每个核心函数建议用以下字段记录：

| 字段 | 应填写的内容 |
| --- | --- |
| 原始名称与位置 | 论文公式编号/页码，或源码文件、类和函数 |
| 输入 | 数据结构、取值范围、来自哪个模块 |
| 输出 | 返回内容、单位及被谁使用 |
| 更新规则 | 原始公式、算法或条件分支；明确是否为自行重建伪代码 |
| 状态变化 | 修改哪些 agent、网络或全局变量 |
| 调度 | 每轮何时执行、同步还是异步、结束条件 |
| 参数依据 | 文献、真实数据估计、作者假设或待核验 |
| 异常处理 | 空消息、失败调用、无邻居、越界值的处理 |

较长材料可以在样例目录新增 `DESIGN.md`、`REPRODUCTION.md`，由该目录 README 链接。已有笔记直接链接，避免复制后出现版本分歧。

## 4. 怎样记录复现

复现前填写软件和语言版本、依赖、数据要求、许可证及执行命令。复现代码放入 `04_code/implementation` 的样例子目录。

运行时将配置、输出和日志分别存入 `06_experiments/configs`、`results`、`logs` 的样例子目录，首次使用再创建。每次记录源码版本、配置、随机种子、实际命令、日志位置、预期结果和实际结果。

“拿到 PDF”“读懂方法”“代码可启动”“复现论文结果”分别登记。仅能启动时，结果复现仍应写“未验证”。失败也保留记录，写清报错、原因判断和后续处理。

## 5. 怎样用于我们自己的模型

将原样例的事实、拟借鉴的设计和实际验证结果分开写。涉及本项目时映射到 `f_message`、`f_selection`、`f_update`，并区分信息来源 LLM 与模拟人的 LLM。

通用工程经验可写入样例档案；正式架构变更写入 `04_code/implementation/ARCHITECTURE_DESIGN.md` 并更新版本。研究问题、构念或边界发生变化时，依项目规则确认并保存变更说明。

## 6. PDF 和 Git 如何管理

当前 `.gitignore` 默认排除 `02_literature/papers` 和 `02_literature/user_supplied_originals` 下的 PDF；HiSim 归档 PDF 已按用户要求添加单文件例外，纳入 Git。可通过 EX001 的 PDF 链接在线阅读或下载。

根目录 `2024.findings-acl.285 (1).pdf` 保留为未跟踪副本，不重复上传。两份文件已核验内容相同，哈希见 EX001 档案。

若后续决定把某篇可共享全文纳入 Git，应明确选择该文件、核验共享条件，并同步修改该文件的忽略规则及在线链接；不要通过全目录强制添加上传所有本地文献。

日常提交前查看 `git status --short`，按明确文件路径暂存，检查 `git diff --cached --stat` 和 `git diff --cached --check`，再提交推送。`SOURCE_MANIFEST.csv` 是迁移来源记录，不用它伪造新增笔记的来源；新增内容由 Git 与样例版本记录追溯。

## 7. 更新版本

纠正文字或链接更新 PATCH，新增设计或复现材料更新 MINOR，改变档案组织规则时更新 MAJOR。每次简述改了什么及依据；模板的空字段不应被当作已经完成的记录。
