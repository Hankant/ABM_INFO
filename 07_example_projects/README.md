# 样例工程库

首次使用请看 [使用说明](USAGE.md)：阅读、新增样例、函数拆解、复现记录、PDF 与 Git 管理。

集中管理值得拆解的样例文献、工程设计、参考代码与复现记录。每个样例有独立档案，可从文献追到设计、代码和验证证据。这里记录原样例及借鉴判断；项目正式架构仍以 [架构设计文档](../04_code/implementation/ARCHITECTURE_DESIGN.md) 为准。

## 材料存放规则

| 材料 | 位置与管理方式 |
| --- | --- |
| 样例索引、设计拆解、来源记录、复现说明 | 本库对应样例目录 |
| 已有原文 PDF | 链接 `02_literature` 的现有文件；用户原文依现行规则仅本地保存 |
| 后续样例 PDF | 在 `02_literature/user_supplied_originals` 保存，并在样例档案登记路径、文件名和实际 SHA-256 |
| 既有知识图谱/文献笔记 | 链接原位置，避免多个副本独立修改 |
| 第三方代码 | `04_code/third_party_reference`，保留作者和许可证；登记 URL、commit/tag 与获取日期 |
| 本项目复现或改写代码 | `04_code/implementation`，明确原创和改编部分 |
| 实验配置、输出、日志 | 首次运行时建立 `06_experiments/configs`、`results`、`logs` 的对应样例子目录 |

本库使用普通 Markdown 相对链接，不依赖 Windows 快捷方式。标明“本地原文”的链接在 GitHub 上不可用；公开阅读入口须单列。不得把未获取或未运行的材料登记成已完成。

## 新样例的工作顺序

1. 复制 [样例模板](templates/EXAMPLE_TEMPLATE.md)，分配稳定 ID。
2. 登记文献与代码来源、获取状态、版本和许可。
3. 拆解对象、环境、状态、函数、调度、数据流与参数出处；每项注明论文页码或代码位置。
4. 记录环境依赖、运行命令与预期输出；实际运行后才登记验证结果。
5. 将拟借鉴部分映射到本项目接口，注明差异与待定项；研究设定变化须按项目规则确认。

状态按材料获取、方法拆解、源码核验、运行复现分别记录，不用单一“完成”替代。
