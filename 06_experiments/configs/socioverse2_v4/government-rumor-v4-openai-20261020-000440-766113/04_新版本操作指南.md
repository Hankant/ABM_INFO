## 2. 基础表变化

保留原有582个ID、305名LLM／277名规则、82／500分组及305份资料对应，不重新抽人。圈内LLM43名、规则39名；圈外LLM262名、规则238名。具体对应仍是实验分配，不是原始账户真实关系。

原字段继续使用：agent_id、decision_mode、group、follows_source、profile_id、sex、location、following_count、followers_count、statuses_count、profile_status、source_rows。

新增以下稳定资料字段：

| 新字段 | 意义 | 本次填写 |
|---|---|---|
| persona_version | 资料版本 | V4 |
| pre_event_experience | 本事件模拟开始前、有依据的相关经历 | 留空，原数据没有提供 |
| sharing_habit | 有依据的一般分享习惯 | 留空，不能用本次转发倒推出一般习惯 |
| initial_source_evaluation | 开始前对原帖来源的评价 | 留空，不能由关注关系代填 |
| initial_government_evaluation | 开始前对政府来源的评价 | 留空，不能自动生成百分比 |
| persona_basis | 资料依据 | LLM为观测快照且行为背景未知；规则用户不适用 |

空值不是0、不是低信任。规则用户仍不生成自然语言人格。若以后补充实验设定或独立资料，需说明来源并升级版本，不能静默填入本表。

## 3. 每个人在程序里保存四份内容

| 对象 | 从哪里来 | 何时改动 |
|---|---|---|
| persona | CSV的稳定属性和事前背景 | 初始化一次，运行内不重写 |
| state | 当前对P001的信念 | 合法决策统一提交后更新 |
| memory | 本人实际观察、判断和已提交行动 | 每次成功决策后追加 |
| observation | 本轮实际展示的帖子和评论 | 每轮由环境生成 |

初始化state.current_belief=unjudged，memory为空；不从评论标签预置相信。unjudged是尚未判断，不等于uncertain。上轮提交后的state总是单独传入，不因记忆窗口缩短而丢失。

例如，A0002过去两轮先不确定、后相信。第三轮输入的是：不变的persona、当前believe、前两轮经历、第三轮新内容。模型可以维持相信，也可以改变；不要求一贯相信来“符合人设”。

## 4. 构建agent操作顺序

1. 创建V4研究版本，读取本目录CSV，不覆盖V3。
2. 映射人群字段，确认305个资料编号在LLM组各出现一次。
3. 按环境文档建立共同网络与排程；两类用户均可通过转发影响对方。
4. 对LLM用户，分别生成稳定资料段、当前信念段、本人记忆段和当前观察段，填入V4固定模板。
5. 对规则用户，使用概率合同，不调用LLM，不读取自然语言记忆推理。
6. 统一校验与提交结果，更新状态、公共评论库和个人经历。当前轮新行动下一轮才可见。
7. 保存实际输入内容、原始响应、解析状态、决策方式、状态前后值和运行模式。dry_run与真实调用分开。

这对应研究层的人群、环境、决策和记录职责，不要求修改SocioVerse2核心引擎。具体字段由构建agent按部署schema映射。[官方架构](https://socioverse.fudan-disc.com/docs/concepts/architecture/)

## 5. V4明确不做什么

- 不把邻居私人相信比例、邻居政府信任均值提供给用户。
- 不把所有评论都当作每个人的记忆；只有实际看到的内容才能进入本人经历。
- 不额外提供评论支持比例；先让模型读取实际可见的评论文本。
- 不随机编造信任经历或按群体强制设定相信倾向。
- 不做LLM自动反思、长期摘要改写人格或动态政府信任更新。
- 不切换成10轮及第2／5／8轮回应；继续沿用环境文件中的40轮、T_G=20等首跑草案。

## 6. 验收检查

先使用固定回答做工程测试，再单独测试真实调用；前者不是研究结果。

| 检查 | 合格表现 |
|---|---|
| persona稳定 | 同一人在两轮输入中的稳定资料完全一致 |
| 状态独立保存 | 删除较早记忆后，当前信念仍为最后一次合法提交值 |
| 私人记忆 | 任一历史条目都能追溯到本人实际观察与行动 |
| 可见性 | 未展示评论、别人的内心判断和未来回应不进入输入 |
| 时间 | 当前轮评论只能在后续轮被其他用户看到 |
| 失败 | 错误不变成uncertain，固定回答不冒充真实LLM输出 |
| 规则纠正失败 | GT失败保持原状态，不把unjudged自动改成uncertain |
| 资料一致 | V3原身份、分组、类型、属性和资料对应未改变 |

此前panel中所有LLM决策为dry_run固定回答，只能作为旧工程测试。V4新增结构必须在实际序列化输入中逐项检查，不能仅凭CSV字段存在宣称已经生效。

如需最小验证，在同一305名LLM子群中依次比较：仅任务与观察、加入稳定属性、再加入历史。验证历史作用时，两组都提供相同定义的当前状态，区别只在是否提供历史经历；不把“去掉当前状态和去掉记忆”混在一个操作中。初步固定外部观察，再做传播反馈；277名规则用户的配置保持一致。

## 7. 运行条件与指标

网络、活跃、阅读、政府实验回应、排程、模型别名及请求/token预算已在环境文件中给出首跑草案，不能再称全部缺失。实际provider、服务凭据和费用限额仍需在运行环境验证。

规则正式条件、重复接触与完整状态合同，以及混合三态下的TBU定义仍须使用明确冻结的版本；已有建议不自动等于已经实现。TBU不得把uncertain当成完成纠正；本次V4不另行更改TBU公式，也不以新persona替代规则参数确认。

## 8. 数据与版本边界

原始资料来自32.weibotest-fupin2_new(1).xls，250条评论与72条转发涉及305个账户。表中只保留可用账户属性与来源行号，不含昵称、主页、真实账户ID或事件评论全文。行号可回查，属于假名化，不是完全匿名；使用范围按研究授权，不自动上传或公开。

一名账户的发博数冲突字段留空；六名不同账户的属性重复待查，相关属性留空。采集时点未证明早于事件，不能作为严格事前心理测量。305名LLM借用这些属性，不等于重建了305个真人；277名规则用户仍是合成人群。

V4主要改动是明确四部分结构、保留独立当前状态、限制个人记忆来源，并新增可追溯的事前背景字段。当前新字段留空是数据边界，不是允许构建agent自行填故事。没有新增未经验证的心理变量实验，没有启动真实模拟。
